Java Coding Guidelines — My View 2

As a senior developer with years of hands-on experience, I’ve encountered countless scenarios where the right coding practices made a significant difference in project outcomes.

If you are not a medium member, read it here.

This article isn’t about preaching universal truths — it reflects my journey and hard-earned lessons in writing better Java code. Think of it as a conversation, from one developer to another, sharing insights that might save you time and headaches.

This piece explores practical, actionable tips to elevate your coding game, from foundational principles to leveraging modern tools like IntelliJ IDEA.

Let’s dive into the Core Java Coding Guidelines and explore how IntelliJ/IDE Support can enhance your productivity.

Core Java Coding Guidelines

Define Hardcoded Values Properly

  1. No Magic Numbers or Strings
    Use constants or enums to make your code more readable and maintainable.
  2. Prefer Enums for Constants 
    Enums are type-safe and more descriptive than using literal constants.
  3. No Hardcoded Credentials or Sensitive Data 
    Never embed passwords, API keys, or sensitive information in your code. Use environment variables or configuration files instead.
If the value is sensitive, store it securely. If not sensitive, define it as a constant or enum.

Avoid Common Pitfalls

4. Avoid System.out Calls

Replace System.out.println with proper logging frameworks like SLF4J or Log4j. Logs give better control and context for debugging.

5. Avoid Deep Nesting

Use early returns to reduce nested blocks and improve readability.

6. Avoid Code Duplication

If you see similar blocks of code, refactor them into methods or utility classes. Keeping your code DRY (Don’t Repeat Yourself) is worth the effort.

7. Avoid unnecessary null checks

Repeated null checks clutter the code and distract from the main logic. Forgetting a null check can result in NullPointerException. The intent of the code becomes less clear when scattered with the null-checking boilerplate. Use Optional instead of null check if needed.

8. Do not reinvent the wheel, Use libraries and frameworks

Use the latest versions of the libraries unless there is a specific reason to use older versions.

Follow Best Practices

9. Follow Java Naming Conventions

Java has well-established naming conventions. For example, class names should be in PascalCase while method and variable names should be in camelCase. Consistency here makes your code look professional and easier to understand.

11. Follow KISS and SOLID Principles
 Keep It Simple, Stupid! Avoid overcomplicating your code without real benefit. Design classes adhering to SOLID principles, like Single Responsibility and Open/Closed Principles.

12. Pay Attention to Thread Safety 
If your application is multi-threaded, make sure shared resources are thread-safe. Use synchronized blocks sparingly as they can impact performance. Explore modern constructs like java.util.concurrent.

13. Use Modern Language Features
 Java has evolved over the years. Use features like:

  • Try-with-resources for auto-closing resources.
  • Lambdas for functional programming.

14. Close Resources Properly 
Use try-with-resources to ensure resources like streams or database connections are closed correctly.

15. Override Equals and HashCode
 When creating custom classes, implement equals() and hashCode() correctly to avoid unexpected behaviour in collections.

16. Use Appropriate Data Structures 
Know your data structures and use the right one for the job. For instance, use ArrayList for fast lookups and LinkedList for frequent insertions.

IntelliJ/IDE Support Guidelines

Your IDE is your best friend. IntelliJ IDEA, in particular, provides powerful tools to improve your coding efficiency.

  1. Comply with Sonar Rules — Use tools like SonarLint to detect issues in real time. These rules enforce standards for clean code.
  2. Use IntelliJ Code Analysis IntelliJ flags potential issues as you type. For a deeper analysis, use Run Inspections under Analyze. You can view detailed results in the browser or within the IDE.
  3. Format Code Consistently Use IntelliJ’s default code formatter or a project-specific formatter. Consistent formatting improves readability.
  4. Leverage Refactoring Tools IntelliJ’s refactoring features are gold. From renaming variables to extracting methods, these tools help maintain clean, error-free code.
  5. Use Static Code Analysis IntelliJ’s inspections can analyze cognitive complexity, duplicate code, and thread safety concerns. Use these insights to improve your code.

Breaking It Down

  • Normally, when overriding a method, the return type must match exactly
class Parent {
    Number getValue() { return 42; }
}

class Child extends Parent {
    @Override
    Number getValue() { return 7; } // Must match exactly
}

  • Java allows the overridden method to return a subclass of the parent’s return type With covariant return types.
class Parent {
    Number getValue() { return 42; }
}

class Child extends Parent {
    @Override
    Integer getValue() { return 7; } // Integer is a subclass of Number
}

COVARIANT 😕?

“Co-” means together
“Variant” means changing
So, In here,
“Covariant” means the return type can change, but only in a way that stays compatible (i.e., it must be a subclass of the original return type).

Why is it useful?

  1. Avoids Casting—you'd need to cast it to Integer in Child If getValue() originally returned,Number but with covariant return types, that’s unnecessary.
  2. Preserve Type Safety—Java validates that the return type in the child is always a valid subtype of the parent’s return type.
  3. Enhances Readability & Usability—The subclass method provides a more specific return type, making the API more intuitive.

This trick is both

✅ Polymorphism (method overriding + runtime method dispatch)
✅ Covariant return type (allowing Integer instead of Number)

No Errors 🔴.. Polymorphism ✅ Answer is 7. [Magic is Code will not give errors because of Covariant Return type]

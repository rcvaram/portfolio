Why Spring Boot’s Default Logging Breaks in Datadog

Datadog treats every single line as a separate log event.

Spring Boot logs are multiline by default — exceptions and stack traces.

Because of this:

  1. More logs = More cost
    One exception stack trace can easily become 20–50 separate logs. Multiply that by a thousand users? Bad Right.
  2. Broken context & Harder troubleshooting
    Stack traces are fragmented. We can’t see the full picture. Hard to find the root cause in search.
  3. Alerting failures
    Alerts based on partial log lines? Useless. We’ll either get flooded or miss real issues.

✅ The Fix: Log in JSON, Not Plain Text

We switched our logs to JSON format using Logstash Logback Encoder.

That way, all our logs — including stack traces — are captured in a single structured log event.

Switch Spring Boot to JSON logs with Logback → Save Datadog cost, fix broken alerts, and make debugging easier. Full setup in 3 steps.

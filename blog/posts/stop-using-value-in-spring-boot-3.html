🛑 Stop Using @Value In Spring Boot 3

Use @ConfigurationProperties with Records Instead

Recently, I saw a PR from my junior. He injects parameters from application.properties to a retry service as below, with the help of the @value annotation service.

Yes, it would work, and it's easy to code as well. As an experienced developer, my mind said — “This won’t scale.”

  1. Scattered configuration — hard to group or refactor
  2. No validation — invalid values silently break logic
  3. Lack of immutability — fields can be changed at runtime
  4. Manual defaulting — @Value("${retry.attempts:3}") starts to pollute logic

SO I requested him to use @ConfigurationProperites

@ConfigurationProperites to bind the external properties from our application.properites/ applicaiton.yaml files to our application

Spring Boot’s @ConfigurationProperties allows us to map grouped properties into a single class.

From Spring Boot 3 onward, it supports Java Records, giving us immutability & type-safety.

  • 🔐 Immutable config using Java Records
  • 🧠 Type-safe and IDE-friendly (auto-complete support)
  • 🧪 JSR-303 validation (@NotNull, @Min, etc.)
  • 🧼 Separation of concerns — config stays out of your business logic
  • ✅ Easier testing — inject mock config beans in unit tests

While @Value might work for small-scale apps or quick prototypes, but it becomes unmaintainable as soon as:

  • You need validation
  • You use multiple related config values
  • You want clean, testable services

By using @ConfigurationProperties With records, you're in a modern Spring Boot approach that gives clean code, type safety, and better separation of concerns.

I follow rule below in my application development

I use @ConfigurationProperties for structured, reusable, grouped config And, I use @Value for quick, simple, or one-time properties.

What Does GroupBy mean in Stream?

I’m assuming you already have experience with Java 8 and are familiar with stream, filter, and map. This would help you understand Groupby.

Let's think we have a list like this,

List<String> names = List.of("Siva", "Sri", "Ram",
                "Kumar", "Raja", "Ranjan",
                "Sutha", "Sankar", "Venu");

We must identify and categorize the names according to their first letters, such as:

So, the first letter of a name must be the same in order for it to be accepted into the group.

Why is the result is Map?

.groupingBy(name -> name.charAt(0))

Imagine that we are going to form a bucket or group. What do we need first?

We should label the group, which is what we do in the groupingBy
We should tell JVM how to label each element in the list.

It will check each element and add it to the bucket or group based on each element key internally after labeling or creating the key.

JVM takes care of the grouping, so this is the only thing we need to accomplish.

For JVM, we only need to identify the key or rule.

In this example, it was,

element first letter

The conclusion is that,

you are responsible for providing the Key, and Stream handles the remaining functions.

Let’s understand the power of groupingBy in Stream

We need to go one step further, such as counting the items in each group, rather than just grouping the elements.

I would write it as follows if I were writing it in Java:

What I did is,

I got the groups then I write another logic to count each group elements.

This is not how you have to do things.

Stream knows about this and lets you pass the function you wish to run in the stream.

I only need to pass the function next to my key identifier/classifier if I want to count it.

We refer this process as a downstream operation.

Check out the mental model below to see what we are actually doing.

So, groupingBy

Let see a few typical downstream processes. To understand easily, let’s look at the employee list below;

1. Counting

We are going to count for each department how many employees are there?

  1. Classifier → Group employees by department
  2. Downstream Operation → count employees in each department.

2. Keep the Elements into List

When you don’t provide the downstream operation, groupingBy will automatically behave like this.

3. Arithmetic operations with elements inside the groups

We might need to sum up each department’s employees salaries rather than counting the elements.

You can use;

  • Collectors.summingInt();
  • Collectors.summingDouble();
  • Collectors.summingLong();

Sometime we need to get the average of employee salary per department.

  • Collectors.averagingInt();
  • Collectors.averagingDouble();
  • Colelctors.averagingLong();

Sometime we need to get the minimum salary or maximum salary employee per department.

  • Collectors.maxBy();
  • Colelctors.minBy();

instead of doing all arithmetic operations, you can do it in single go like below by summarizing it.

  • Collectors.summarizingInt();

This provides average, sum, max,min, count.

4. Mapping inside the group — Most of the realworld problems

We are able to transform employee into employee name and do the grouping.

Instead of getting employees, we get names only for each department.

If necessary, you can connect the string rather than collecting a list.

5. CollectAndThen

It gives more flexibility for developers to execute the custom logic inside each group.

I hope you now have a better understanding of GroupingBy and its potential power with Java Streams.

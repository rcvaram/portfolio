Tackle the Multi Log Line issue in Datadog for the Spring Boot 3 App

This story covers how our team fixed the common issue in application logs when we export to Datadog. 

Datadog expect each line to be a separate log.

exceptions, stack traces, or verbose outputs — span multiple lines with a default logging in Spring boot App.

Beacause of that, Datadog

  • Increase log ingestion costs (each line counts as a separate log)—splitting a single multi-line log into a huge separate line can unnecessarily multiply our log volume.
  • Break a multi-line log into multiple single-line logs
  • Lose context (stack traces get fragmented) — We might be unable to search for full exceptions or patterns properly.
  • Troubleshooting issues — It’s harder to correlate errors or understand the full context of issues when logs are split.
  • Causes alerting errors (missing crucial error details)—Alerts based on partial logs may fire incorrectly or miss the real root cause.

How to fix this?

We fixed the format of the Spring Boot application logging. 

Instead of log it in plain text we log it in JSON.

This is how we setup

Step 1 Add Required dependencies

Step 2 Add logback XML

<?xml version="1.0" encoding="UTF-8" ?>
<configuration>
    <property name="DEV_HOME" value="/app/medium-log-app"/>
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <encoder class="net.logstash.logback.encoder.LogstashEncoder">
            <version>1.0.0</version>
        </encoder>
    </appender>
    <logger name='MediumApp' level="info" additivity="false">
        <appender-ref ref="STDOUT"/>
    </logger>
    <root level="info">
        <appender-ref ref="STDOUT"/>
    </root>
</configuration>

Step 3: Run your application


You can check the JSON log format by extend the {…}

I installed Pretty JSON log parser plugin for the IntelliJ that's why this log json format the message, timestamp and level we get in lines. 
Plugin Link : https://plugins.jetbrains.com/plugin/24693-pretty-json-log

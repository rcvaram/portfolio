1. What is an index in a database?

An index is a data structure that improves the speed of data retrieval operations on a table. The database uses the index to locate rows quickly instead of scanning the entire table (full table scan).

Most databases use B-tree structures internally, where data is sorted and can be searched efficiently using binary search.

2. How does indexing actually work?

When an index is created on a column:

  • The database builds a separate structure (B-tree / Hash).
  • It stores column values and pointers (row addresses)
  • Values are sorted, enabling fast lookup

So instead of scanning all rows:

  • DB navigates the tree → finds value → jumps directly to row

This reduces time complexity from

  • O(n) → O(log n)

3. Types of Indexes?

  • Primary Index — Automatically created on primary key
  • Unique Index — Ensures uniqueness
  • Single-column Index — One column
  • Composite Index — Multiple columns
  • Clustered Index — Data stored physically in index order
  • Non-clustered Index — Separate from actual data
  • Full-text Index — For text search
  • Hash Index — Fast for equality comparisons

5. What is a composite index and when to use it?

A composite index is an index on multiple columns.

CREATE INDEX idx_item ON items(item_number, is_split);

This index works well when the query uses columns in left-to-right order.

  • WHERE item_number= ‘1234223’ AND is_split= ‘EA’; — ✔ Works Well.
  • WHERE is_split=’EA’; — ❌ Not effective.

6. What is index selectivity?

Selectivity refers to how unique values are in a column.

  • High selectivity → good index (e.g., item_number, is_split)
  • Low selectivity → poor index (e.g., is_split, name, size)

Indexes are most effective when they reduce result size significantly.

7. When will an index NOT be used eventhough its read operation?

  • Using functions:
WHERE LOWER(item_number) = 'abc'

Index stores original values (e.g., ABC, Abc). DB must apply LOWER() to every row first. So it cannot use the index directly

  • Leading wildcard:
WHERE item_number LIKE '%cd'

Index is sorted from left → right. DB can only search efficiently if the prefix is known.

  • Low selectivity columns
  • Type mismatch
  • Small tables (DB prefers full scan)

Indexes work best when:

  • Direct comparison is possible
  • Data is highly selective
  • Query matches index structure

Indexes fail when:

  • when Data is transformed (functions)
  • when Data starting point is hidden (wildcards)
  • when Data don’t filter enough rows (low selectivity)
If the database could not directly navigate the index (due to transformation, ambiguity, or low filtering), it falls back to a full table scan.

8. What are the drawbacks of indexing?

  • Increased storage usage
  • Slower INSERT/UPDATE/DELETE (index maintenance)
  • Fragmentation → requires rebuild
  • Over-indexing → optimizer confusion
  • Not useful for all queries

9. How do you optimize a query?

  • Use proper indexing
  • Analyze execution plan (EXPLAIN)
  • Avoid SELECT *
  • Limit results (pagination)
  • Avoid functions in WHERE
  • Optimize joins (use indexes)
  • Use caching
  • Avoid N+1 queries
  • Batch operations
  • Maintain DB (stats, rebuild indexes)
  • Partition large tables

10. What is EXPLAIN and why is it important?

EXPLAIN shows how the database executes a query.

Usally it is used to identify:

  • Full table scans
  • Index usage
  • Join order
  • Cost of query

This is the most important tool for optimization.

12. What is the N+1 query problem?

Happens when one query fetches a list, and additional queries are executed per row.

  • 1 query → items
  • N queries → each user’s orders

Fix:

  • Use JOIN
  • Use batch fetching

13. What is index fragmentation?

Over time, index pages become unorganized whih makes queires slow. It can be fixed by rebuild or reorganize index.

14. What is database partitioning?

Splitting large tables into smaller pieces (partitions). It will help to faster scans and better performance on large datasets.

15. Query is slow. What steps will you take? (Real World Example)

  1. Check query using EXPLAIN
  2. Identify full table scans
  3. Add/adjust indexes
  4. Remove unnecessary columns (avoid SELECT *)
  5. Optimize joins
  6. Check for functions in WHERE
  7. Use pagination
  8. Consider caching
  9. Review data size & partition if needed

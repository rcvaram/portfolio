Throttling management in Kong CE

Throttling is a process that is used to control the usage of APIs by consumers during a given period. Throttling and rate-limiting are looking like same as defines the limit for a given period; however, in purpose wisely, they are different. More than that, the period of limits usually higher in throttling than rate limiting.

Kong CE doesn’t have a separate plugin for throttling. As a workaround, rate-limiting plugin is suggested with high limits such as day, month, year for throttling. Throttling can be achieved using the rate-limiting plugin in Kong CE with the limit of the day, month and year. This plugin is not supported to limit a weekly basis.

The cluster, Redis policies can be used when we want more accuracy. As accuracy is of lesser importance, the local policy can be used in the rate-limiting plugin. Most likely, the user will be granted more than was agreed when using the local policy, but it will effectively block any attacks while maintaining the best performance.

For the mock implementation, we want to install kong, Konga and setting up a mock service. These can be followed in the ​​Rate limiting with Kong page.

After setting up the mock fake-api service, rate-limiting plugin can be plugged in the service level with the limit of the day, month and year. Click on the JSON-placeholder service, select the plugins tab and add a new plugin. When you click add plugin button, you will see a pop-up menu which contains plugins. Select the category as Traffic Control so the pop-up menu plugins will change. rate-limiting plugin will be there and click add plugin under the rate-limiting plugin.

Throttling will be imposed per day/week/month basis per client; this is the requirement which is mentioned in the Platform and Monetization Strategy document. The rate-limiting plugin supports the requirement without imposing a limit per week for the client. We have a concurrency problem in this plugin.

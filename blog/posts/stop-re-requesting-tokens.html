Stop Re-requesting Tokens

If your app keeps running to the API door asking for a new token every time, it’s like a nervous child knocking again and again. Slow…

Stop Re-requesting Tokens

Imagine you’re boarding a bus every morning. Instead of buying a monthly pass, you run back to the counter for a new ticket every single ride.

That’s exactly what happens when your app keeps re-requesting tokens. It doesn’t need to.

External APIs often require short-lived tokens.

If you are gonna re-request tokens every time, your app gets slow, verbose, and sometimes blocked.

This Story explains a battle-tested pattern that keeps tokens valid in memory, refreshes them only when needed.

The Big Idea

  • Keep one in-memory token instance.
  • Before using the token, check if it’s expired.
  • refresh If expires— but only once, even if multiple threads are looking into it.

If you’ve worked with REST APIs that use OAuth2 client credentials, and to understand You just need some Java basics — and to know what a token looks like.

Read it here if you are blocked by paywall.

We will have 4 classes.

  1. APIConfig — configure client_id / secret, paths, and give a RestClient bean.
  2. APITokenConnector — makes the actual call to get a token.
  3. TokenHandler — keeps the token in memory, refreshes when needed.
  4. Token record —just a simple class holding access_token, expires_in, issued_at.

APIConfig

This reads values from application properties and creates a RestClient for HTTP calls.

This is the central place for connection details and a single HTTP client to reuse.
@Configuration
@ConfigurationProperties(prefix = "api")
@Setter
@Getter
public class APIConfig {

    private String clientId;
    private String secret;
    private String tokenPath;
    private String basePath;
    private String apiPath;
    private long tokenValidityThreshold;

    @Bean
    public RestClient restClient() {
        return RestClient.builder()
                .baseUrl(basePath)
                .build();
    }

}

APITokenConnector

This guy knows only one job:
It call the token endpoint, parse the response, and give us a Token.

This classs takes responsiblity to network and parsing logic away from token storage.
@Component
public class APITokenConnector {


    private final MultiValueMap<String, String> tokenData = new LinkedMultiValueMap<>();
    private final String tokenUrl;

    private final RestClient restClient;

    public APICTokenConnector(APIConfig configs) {
        tokenData.add(Constants.GRANT_TYPE, Constants.CLIENT_CREDENTIALS);
        tokenData.add(Constants.CLIENT_ID, configs.getClientId());
        tokenData.add(Constants.CLIENT_SECRET, configs.getSecret());
        tokenUrl = configs.getTokenPath();
        restClient = configs.restClient();
    }

    public Token getToken() {
        return restClient.post().uri(tokenUrl)
                .header(Constants.CONTENT_TYPE, Constants.APPLICATION_FORM_URLENCODED)
                .body(tokenData).retrieve()
                .onStatus(HttpStatusCode::is4xxClientError, (req, res) -> {
                    throw new CustomException("Client error while retrieving token: " + res);
                })
                .onStatus(HttpStatusCode::is5xxServerError, (req, res) -> {
                    throw new CustomException("Server error while retrieving token: " + res);
                })
                .body(Token.class);
    }

    private static class Constants {
        private static final String GRANT_TYPE = "grant_type";
        private static final String CLIENT_ID = "client_id";
        private static final String CLIENT_SECRET = "client_secret";
        private static final String CONTENT_TYPE = "Content-Type";
        private static final String CLIENT_CREDENTIALS = "client_credentials";
        private static final String APPLICATION_FORM_URLENCODED = "application/x-www-form-urlencoded";

    }

}

TokenHandler

This is the in-memory token manager.

It remembers the token. It checks if it’s valid. And if not, it refreshes safely.

if it is invalid, synchronizes a refresh against the token endpoint so only one thread performs the refresh.

It prevents multiple requests to get token and keeps code that needs the token simple (tokenHandler.getToken()).
Slf4j
@Component
public class TokenHandler { // In memory instance of the token
    private Token token;
    private static final int MILLISECONDS_IN_A_SECOND = 1000;
    private final APIConfig apiConfig;
    private final APITokenConnector apiConnector;

    public TokenHandler(APITokenConnector connector, APIConfig config) {
        this.apiConnector = connector;
        this.apiConfig= config;
    }

    public boolean isTokenValid(Token token) {
        long tokenIssuedAt = token.issuedAt();
        // x1000 for millisecond time
        long tokenExpiredIn = token.expiresIn() * MILLISECONDS_IN_A_SECOND;
        long now = Instant.now().getEpochSecond() * MILLISECONDS_IN_A_SECOND;
        long tokenValidityThreshold = apiConfig.getTokenValidityThreshold() * MILLISECONDS_IN_A_SECOND;
        return now + tokenValidityThreshold <= tokenIssuedAt + tokenExpiredIn;
    }

    public Token getToken() {
        if (token != null && this.isTokenValid(token)) {
            log.info("Memory Token is valid till : {}", token.expiresIn());
            return token;
        }
        synchronized (this) {
            // If already another thread has updated the token, simply return the token
            if (token != null && this.isTokenValid(token)) {
                return token;
            }
            log.info("InMemory token is invalid, calling the API Token Endpoint");
            Token updatedToken = this.apiConnector.getToken();
            this.token = updatedToken;
            return updatedToken;
        }
    }

}

How to Use?

If another service wants to call the API:

Token token = tokenHandler.getToken();
String accessToken = token.accessToken();
// Use accessToken in Authorization header for requests

That service never needs to know how the token was retrieved — it just asks TokenHandler. TokenHandler hides the pain.

Quick FAQ

Q: How often will the token be requested?

Only when expired or about to expire.
Otherwise getToken() returns the saved token.

Q: Shared across threads?

A: Yes — TokenHandler stores one token instance and uses synchronized to make sure only one thread refreshes it at a time.

Q: What does tokenValidityThreshold do?

A: A small safety buffer so we refresh before expiry.

This makes

  • one place to fetch tokens,
  • one place to keep the token,
  • and a safe refresh mechanism so our app doesn’t ask the token endpoint more than it needs to.

It’s a small, practical module that makes token usage easy for the rest of our application.

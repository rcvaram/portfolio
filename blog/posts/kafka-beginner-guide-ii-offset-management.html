Kafka Beginner Guide II → Offset Management

Kafka Producer is really simple. We may need to tweak some parameters to get the production-ready Kafka producer. On the other hand, If we look at the consumer, Ok why need to look? let’s deep dive into the consumer.

Kafka Consumer

  1. The consumer is used to consume the data from the Kafka Topic. 
  2. When one consumer consumes the data from Kafka, Typically the consumer will belongs to one group.
  3.  Within the group, consumers work synchronously.
  4. More than one consumer will not be assigned to a single partition at a given time within the group.
  5. Consumers will read the data sequentially within the partitions and if more than one partition is assigned to a consumer then the consumer can read the data parallel across the partition.
  6. Consumer group can be looked at as logical single consumer application where that application can read different data from the same topic with the help of partitions and consumers. 
  7. When multiple consumers are subscribed to a topic and belong to the same consumer group, each consumer in the group will receive messages from a different subset of the partitions in the topic.

Offset

Offset is a kind of an id of the message within the partition. The combination of topic name, partition number and offset will be unique for each message which means offset is used to identify the place of the message within the partition.

Consumers will use this offset to know where are in the partition. 

Consumers need to consume the messages and then process the messages. after that, they need to tell Kafka that at what place they complete the processing. 

Consumers use two kinds of offsets and they are 

  1. Current offset
    the position which is currently consumed by the consumer. 
  2. Committed offset
    the last position which is successfully processed by the consumer. 

Who handles this current offset and committed offset? Kafka will not handle them then who? this is the job of the consumer. Consumer needs to track their offsets. That’s how Kafka is designed. Pretty interesting right?

When a consumer consumes messages from Kafka. Consumers need to tell Kafka that, at what place they processed. This action is called commit when the consumer commits an offset of a particular partition that means up to that position consumer processed the messages.

[5+ Years Experienced] Collections Framework Interview Q&A

This article brings you depth knowledge in collections from an experienced developer perspective. Lets Jump into the questions straight away…

1.What is Java Collection Framework?

A framework to store, modify, and manage the groups of objects efficiently.

It provides

  1. Ready-made implementations of common data structures → List, Set, Queues and Maps
  2. Utility classes to help common tasks convinient → Collections, Arrays and Comparator

Basically, Collection framework get rid of building data structures from scratch from developers. Collection frameowork provides cleaner code, reduced bugs and better formance for these data strcutures along with common algortihms and utility functionalities.

2. What is the difference between set, list and map?

List

Its a sequence way of having elements in memory where duplicates are allowed.

Since its sequence way, we know the exact memory address of element via index. So accessing elements is fast. This would be better when we need frequent access to elements with order manner /iterations such as playlist items, ordered menus and user history.

List Implementations

  • ArrayList
  • LinkedList
  • Vector

Set

It is a collection where duplicates are not allowed. It doesn’t maintain positional indexes.

Ordering depends on the implementation of Set

  • HashSet — No ordering
  • LinkedHashSet — insertion order
  • TreeSet — Sorted Order

Set is perfect for storing IDs, emails or any data requiring uniqueness

Map

It is a collection where we can store key-value pairs. Keys must be unique since they are used to identify the pair.

Ideal for lookups and fast searches, caching and configuration management.

Implementations

  • HashMap
  • LinkedHashMap
  • TreeMap
  • HashSet
  • ConcurrentHashMap

So answer is

List storing elements in sequential manner and allowing duplications. Set doesnt allow duplicates and its order depends on the implementation. Map is used to store the key-value pairs.

3. What is the difference between arraylist and linkedlist?

ArrayList

First think how both them implemented. once you understand the implementation, you know the difference easily.

ArrayList implementation is based on array with dynamic behaviour in sizing.

Array means its way to store elemens in contiguous memory.

Since its contiquous memory, you can directly access the element via index and it only takes O(1).

Since arrayList backed up with array, arrayList stores the element in contiquous memory in fixed size array (size 10). once the array is full and a new element is arriving to the element the array of elements are copied and move to another array with the size of 1.5 size of previouse size.

So the size changes like 10, 15, 22, 33, 49

When we delete an element from this array, elements needs to be moved that’s why deletion and insertion takes O(n).

ArrayList is powerful when you need to frequently reading the data instead of modifying it.

LinkedList

It is a way to connect two nodes with links. nodes are linked to form an list.

NodeA — NodeB — NodeC — NodeD — NodeE

Class Node <T> {
private T value;
private Node next;
private Node previous;
}

You can see the node class here you linked previous and next node references. So you create a link between nodes.

Insertions and deletions are extremely efficient as only pointer changes are needed.

For example
If you need to add a NodeP to the list what we need to do exactly?
You will add NodeE next node as NodeP and NodeP previous node as NodeE. Addition is that simple

Incase if you need to remove the NodeB then,NodeB the previous node is NodeA and next node is NodeC. You change the next pointer of NodeA to NodeC and NodeC’ previous pointer to NodeA. the you delete the NodeB oject.

However, Accessing elements is slower because it must traverse nodes sequentially and It would cost O(n) operation.

LinkedList is perfect when you need to frequently add and delete elements from the list.

Choosing these two entirely depends on access versus modification patterns.

4. What is the difference between HashSet and TreeSet?

Stores elements in an unordered manner. Actually it uses hashmap internally.. This is the most the efficient set implementation when ordering is not important.

It provides O(1) for add, remove lookup operations because it relies on hashing.

Treeset strores elements in a sorted manner using a red-black tree. Every insertion involves maintaining sorted order, making operations slower than hashset.

What actually difference
Both are not allowing duplicates however, HashSet prioritizes the performance while treeset prioritizes sorting.

5. What is Iterator in Java and why it is used?

Iterator is a cursor implementation to traverse through a collection in a sequential way.

It supports three methods.

  • hasNext() — check whether if more elements exist
  • next() — to fetch the next element
  • remove() — to remove an elemet from the collection safely.

The advantages are

  1. It provides a universal way to traverse through collections as index traversal only supported in list implementations.
  2. It supports deletion while iterating.
Iterator is a foundation of collection traversal.

6. What is the difference between Iterator and ListIterator?

As I said, iterator is used to traverse through any collections but ListIterator works only with List implementation with more functionalities.

Iterator supports only forwared traversal and the list iteration supports both forward and backword traversals.

Iterator only allows remove elements during the iterations safely but the list iterator supports both adding and removing the elements during the iteration.

List itearation provides some more methods such as previous(), nextIndex() and previousIndex() for bidirectional operations.

Iterator is foundation of collection traversal. ListIterator is list specific and feature rich implementation.

7. What is fail-fast in java collections?

This is a mechanism where iterator fails the iteration immediately thrown the ConcurrentModificationException to ensure the collection is not in corrupted states, infinite loops or inconsistent data.

When an operation changes the collection size or structure then it is considered as structural modification operation.

Add , remove , clear

Set is not usually an modification operation as the size remains same

set(index, value);

When you do the structural modification, data structures track it with modCount.

When collection is iterated, the iteration logic always check whether the modCount == execptedModCount and if both are not equal then it will throw ConcurrentModificationException.

8.Why do we need fail-fast in Java collections?

To prevent unpredictable behavious and ensures safetly. Coz, as I said earlier, modifying a collection while iterating can cause correpted states, infinite loops and inconsistent data.

9. What is the difference between HashMap and Hashtable?

Hashtable is a hashmap where all methods are synchronized. so concurrent modifications is not going to affect the hashtable however the performance will be degraded as all methods are synchronized and only one thread is allowed to perform operation in the map at a time.

Hashtable provides thread safe ways for methods however compound operations are still need external synchronization

if (!map.contrainsKey(x)){
   map.add(x);
}

This is not atomic in hashtable as well.

Hashmap allows one null key and multiple null values, while hashtable doesnt allow null keys or null values.

10. What is LinkedHashmap and when should you use it?

Similar to HashMap but maitains insertion order or access order.

It uses a double linked list that connects all entries in addition to the hash table. This allows for predictable behaviour.

When configured, it moves an entry to the end of the list every time it is accessed. This makes it extremely useful for implementing Least Recently Used caches.

O(1) for insertion, deletion and lookup with slight overhead ofr maintaining the linkedlist.

When you need predictable order or caching behaviour. common use cases include sessions, token storage and caching frameworks.

11. What is treeMap and how it differes from HashMap?

TreeMap is backed with red-black tree instead of array. The time complexity is increased to O(log n) instead of O(1) because operations involve tree balancing.

Keys must implement Comparable or be provided with a custom Comparator

Stores entries in sorted order, allowing range queries, floor, ceiling, naivgational views.

It consumes more memory due to tree nodes and balancing data.

It doesnt allow null keys.

12. What is CopyOnWriteArrayList?

A thread-safe version of array list and optimized for scenarios where reads are frequent and writes are rare.

Instead of synchronizing access, it creates a new internal array everytime an add, remove or set operations occurs.

So writes are expensive because they involve copying entire list but reads are exteremely fast and require no locking which makes it highly scalable.

Iterators never throw ConcurrentModificationException as they operate on a snapshot of the list.

13. What is Comparable?

Defines a natural ordering for class. Within the class, the implementation will be done inside the compareTo method. This makes the class self-sorting.

This is ideal approach when objects have one consistent default order however it is less flexible.

Collections.sort(list) use to sort the list of objects with comparable approach.

14. What is comparator?

Defines sorting logic externallly and allows multiple sorting strageries. It does not require modifing the class.

When sorting depends on different business cases, then this comparator approach is useful.

This is more flexible becuase you can create unlimited sorting rules without modifing the source class.

Collections.sort(list, comparator) is used to sort the list of objects with compartor.

15. Why is Equals(), hashcode() methods important in collections like HashSet or HashMap

HashSet & HashMap rely on hashing to determine the bucket of an object.

hashcode() determines the bucket where the object is stored.

equals() determines whether the object already exists in that bucket.

If two objects are equals according to equals() they must produce the same hashcode.

Two objects with the same hascode are not required to be equal.

16. When will you use array List and when will you avoid array list?

You can use it

  • When we need fast access via indexing.
  • When you dont need thread safety and your insertions and removals mostly at the end.

Dont use

  • Frequent insertions and deletions in the middle
  • Large shifts in elements ( reallocation is expensive)

17. How do you choose the right approach to sort a List?

Collections.sort(list)

If you need a simple sorting / natural sorting, you can do it with Collections.sort() It modifies the original list in places. For example, you have a list of Strings or primitive types, objects that implement Comparable

Collections.sort(list, comparator)

Implements Comparator<T> seperately from the class. When multiple sorting orders are needed and you need to seperate the sorting logic from the original class.

class ArticleLikesSorter implements Comparator<Article> {
    @Override
    public int compare(Article a1, Article a2){
        return Integer.compare(a1.getLikes(), a2.getLikes();
    }

}


List<Article> articles = List.of(a1,a2,a3,a4,a5);
Collections.sort(articles, new ArticleLikesSorter());

18. How do you decide which Set implementation to use?

HashSet

It is best for fast lookups and you dont care about ordering. Dont use when you need thread safety and preserve insertion or sorted order.

LinkedHashSet

It basically extends the hashset with maintains insertion order. Slightly slower than HashSet When you need predictable insertion order and fast operations, you might take this option.

If you don’t need ordering then go with hashset and also, if you need sorting with different mechanism use treeSet

TreeSet

It implements NavigableSet Maintains elements in natural or custom sort order. It is backed a red-black tree.

Use TreeSet when you need sorted elements, range based queries(subset, headset, tailset).

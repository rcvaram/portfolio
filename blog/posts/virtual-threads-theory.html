Virtual Threads — Theory


Platform Threads

  • Platform Threads — Thin wrapper over OS threads [when JVM creates threads it will request to OS to create a thread]
  • One to One mapping with OS threads
  • Thread pools

Virtual Threads

  • Lightweight user threads
  • Highly scalable
  • No need for pooling — Pooling is an antipattern for virtual threads
Virtual Threads alone can’t do any work. They required platform threads to do the task. Basically, virtual threads will be carried out by platform threads.

You can understand now, that there is a time when platform threads can not carry out virtual threads. For example, if we have 5 platform threads and 20 virtual threads, at one point of view time, only 5 virtual threads are connected to platform threads. so what will happen to the other 15 virtual threads? Actually, this responsibility is taken care of by the virtual thread scheduler. 

The virtual thread scheduler mounts the virtual thread onto a platform thread when required. and unmount the virtual thread from a platform thread when it is not required such as virtual threads are waiting on something.

Virtual threads can be waiting due to some IO operations

  • Network resources to be available
  • waiting for DB call response
  • waiting for the external server response
In a typical I/O-bound application, threads spend a lot of time waiting, and if we use virtual threads, we can simply avoid this waiting. 

 You understand virtual threads are mounted and unmounted to platform threads. due to this mount and unmount only we can create millions of virtual threads without worrying about resource consumption How does Java do this? the answer is Continuation 

Continuations

We can simply say a representation of the current state of the program. 


Abstract view of virtual thread with continuations

Basic needs

  •  A virtual thread should not use CPU when it is waiting/blocking
  • A virtual thread can get mounted on several platform threads during its lifetime
  • A platform thread can support several virtual threads during its lifetime. 

To design this,

We need a virtual thread class, a virtual thread scheduler to mount & unmount these virtual thread objects to platform threads. 

A simple version of Virtual Thread Class

public class VirtualThread {
  private Continuation continuation;
  private int id;
  private static final AtomicInteger COUNTER = new AtomicInteger(1);

  public VirtualThread(Runnable runnable) {
    cont = new Continuation(...)// initialize a continuation
    id = COUNTER.getAndIncrement();
  }

  public void run() {
    log.debug("Virtual Thread : {} is running on : {}", id, Thread.currentThread());
    cont.run();
  }


}

A simple version of VirtualThreadScheduler Class

public class VirtualThreadScheduler {

  private Queue<VirtualThread> queue = new  ConcurrentLinkedQueue<>();
  private ExecutorService executor = Executors.newFixedThreadPool(n);
  
  public void start(){
    while (true) {
      if( !queue.isEmpty()) {
          var vt = queue.remove();
          executor.submit(vt::run);
      }
    } 
  }


  public void schedule(VirtualThread vt){
    queue.add(vt);
   }



}

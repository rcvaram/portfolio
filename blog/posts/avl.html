AVL

BST means Binary Search Tree. In BST, We arrange the values of the BST such that any node, for all elements on the left side, is smaller than that node and right side of all elements of that node will be greater than that node.

 Why we need to arrange the elements like because it can be used to search the particular element very fast and also we can get the elements in sorted order when we traverse the tree as in order manner.

Suppose we need to search an element 6 in this binary tree. When we look at a node value with respect to our search element. if the node value is smaller than search value we look the right side of the tree and if the search value is smaller than node value then we look left side of the tree. if node value and the search value are same then we found the place of that element. when we reach leaf that means there is no element in that BST.

if we have 6 first we check with 5 and 6 is greater than 5 so we look right side tree. then we compare 6 and 7 here 6 is smaller than 7 so we look the right side of 7 we will compare node value 6 and search value 6 both are same we found the element. cool

for 10

  1. 10 and 5 compared
  2. 10 and 7 compared
  3. 10 and 8 compared
  4. 8 is a leaf node so we reach the tree and could not find the element which means 10 is not in the BST.

What’s the problem with BST?

When we create a BST, we will first check with root whether it is greater than root or smaller than root. based on that, we can move to the right side or left side. we move the element until we reach the leaf node. and we put the element there.

When we have values to create the BST, the order of values are important since it decides the height of the tree. It can be O( logn) or O(n). If the height is log n then the search will take log n and if the height is n then the search will take n. if it is n then the search is similar to linear search. 

The main drawback of BST is the height of BST depends on the insertion order. 

You might think that how many orders are possible for given n values. it is n!. if we have 3 elements we may have 3*2*1 = 6 orders.

Do you think? It is possible to get small height binary tree to reduce the searching time since searching time is proportional to tree height.

We can, How? we perform rotations to find minimum height BST for given inputs.

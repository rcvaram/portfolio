Got Runtime Error Because of IntelliJ Suggestion

IntelliJ IDEA suggested using stream.toList() instead of stream.collect(Collectors.toList()). I changed and Boom!!!!! Got a runtime Error UnsupportedOperationException

I was working on a feature where I had a list of Item objects. I need to perform stream operations to filter and transform these items into a new list.

After creating this list, I needed to remove certain elements based on specific conditions to clear up the invalid items from the list.

List<Item> items = getItems(); // Retrieve a list of Item objects

// Stream operation to filter and collect into a list
List<Item> filteredItems = items.stream()
                                .filter(item -> item.isActive())
                                .toList(); // IntelliJ suggests using toList()

//sample scenario 
filteredItems.remove(0); // Throws UnsupportedOperationException

IntelliJ suggested replacing it collect(Collectors.toList()) with toList() for simplicity.

I accepted the suggestion, and everything was compiled without issues. However, when I ran the code, I encountered UnsupportedOperationException at runtime.

My Code crashed with an exception when trying to remove an element from the list. This put me to investigate why this happened.

The Root Cause: Immutability of toList()

toList() returns an unmodifiable list. If we make any attempt to modify the list, such as adding or removing elements, will result in a runtime error.

The immutability of toList() gives safety in cases where the list is meant to be read-only, but it’s not good when you need to modify the list.

So in my case, I need a mutable list.

can I use collect(Collectors.toList()) without worrying about IntelliJ's suggestion.

Let's check the official documentation.

They told us in the documentation → there is no guarantee which kind of list implementation is provided for you by the java implementation.

In most Java implementations (such as OpenJDK), Collectors.toList() returns an ArrayList.

Collectors.toList(): Returns a List (implementation depends on the JDK).

So, while ArrayList is the default, theoretically, another List implementation (such as LinkedList) could be used.

Now we understand simple toList() should be avoided for our use case. and Also, Collectors.toList() can be an issue when java implementation takes place.

The Ideal Fix → Use Collectors.toCollection()

List<Item> filteredItems = items.stream()
                                .filter(item -> item.isActive())
                                .collect(Collectors.toCollection(ArrayList::new));
filteredItems.remove(0); // Works fine

Mutability is achieved and also we know which type of list is used to collect the elements. Collectors.toCollection(ArrayList::new): Returns a mutable ArrayList.

toList() is simple & convenient, it should be avoided in scenarios where the list might need to be modified.
Using Collectors.toCollection(ArrayList::new) ensures that we are working with a mutable list (like ArrayList) and prevents unexpected runtime errors.

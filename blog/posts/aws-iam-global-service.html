AWS — IAM (Global Service)

Identity & Access Management 

 IAM is a kind of service where you can manage your users. A root user / Root account is created by default. This should not be shared/used since It has all permissions to perform any actions to your resources. What is the use of this account? To set up an administration account for you to utilize the AWS services. 

How to allow others to use your AWS account? As you know, to use your AWS resources, you have to give permission. These permissions can be JSON documents and are called policies. These policies can be attached to the user/group. Basically, with these policies, we can define the permissions of the users. These users will be shared with others to use your AWS account.

Least privilege principle

Don’t give more permissions than a user needs

Users are people within your organization and can be grouped. Groups can have multiple users, not other groups. but the user can be a stand-alone user which means the user must not be within a group. Users can be within multiple groups as well. 

Policies Depth

When a policy is attached to group level then it will be applied to all the users within the group. As I said above, some users may not be belong any groups in that time assigned policy for the user is called inline policy.

IAM Policy Structure

  • Version → The policy structure version
  • ID → An optional parameter ot identify the policy
  • Statement → describe a permission so a policy can have multiple statements.
  • Statement → id → identifier for the statement which is an optional parameter
  • Statement → effect → Permission effect basically the permission is used for allow or deny the access
  • Statement → Pricincipal → account/user/role to which this policy applied to
  • Statement → Action → List of actions that the particular permission/statment allows or denys
  • Statment → Resource → List of resources where the actions can be performed. 
  • Statement → Condition → Conditions for when this policy is in effect

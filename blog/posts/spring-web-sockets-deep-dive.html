Spring Web-Sockets Deep Dive

This is not really needed to work with web-sockets in spring however it will give clear cut idea what / why / how questions for web-sockets in spring

Web-Sockets features in Spring

  • Fallback options with SockJS
  • Support for STOMP subprotocol
  • No security — [Spring Security can be added to the top of this layer]
  • Integration with messaging components and Spring programming style

STOMP Introduction

Simple interoperable protocol for asynchronous messaging. This allows communication between client and server is through a frame.
Client frames:
• SEND, SUBSCRIBE / UNSUBSCRIBE, ACK/NACK
Server frames:
• MESSAGE, RECEIPT, ERROR

Understanding the work flow

Overview

Client will send a stomp message to web socket endpoint. Here, endpoint role is receiving the message , decoding the message, delivering to a channel and publishing application events. This web socket endpoint also finds the right sub protocol handler. By default, it will take STOMP as sub protocol handler if nothing is defined.

@Configuration
public class WebSocketConfig extends WebSocketMessageBrokerConfigurationSupport {
  public void registerStompEndpoints(Stomp EndpointRegistry registry) {
  registry.addEndpoint("/ws").withSockJS();
  }
// remaining code ...
}

We are defining this endpoint “/ws” to enable the websocket connection /session through this endpoint with callback option to ensure even if the client doesn’t support websocket. 

This message will be pushed to client inbound channel [Kind of queue to hold the messages]. This channel / queue may have several subscribers and these are called as message handlers. 

Message handlers are the real guys who is going to process the actual message. These handlers may send response to clients as well. In that case, response will be sent to client outbound channel and then it will be forward to through web socket session.

Transactional Propagation

java.sql gives connection interface and relevant database(datasource) you added to the code will give actual implementation of connection interface. this interface provides rollback(), commit(), close().

When a method is annotated by @Transaction then datasource create a connection for the code execution in that case,

Since ProductService and ProductRepository have @Transaction annotation, will do have two connection? or single connection?

Now you need to make a decision on this. How database create/use connection for transactions. that’s where Propagation is used.

When a method is annotated with @Transactional , We can give propagation level to tell the spring that how it should use the active transaction for the current transaction. 

When we dont give any propagation level then Spring check whether the code belongs to an active transaction or not. If it belongs to an active transaction then its not going to create an new transaction and existing code will run in the same transaction connection. If it doesnt have an active transaction then it will create a connection to run the transaction code. Basically, when the code is in the @transaction then it requires a database connection and if connection already exists then it will run otherwise it will create. This propagration level is REQUIRED.

If you see in this example, the CustomerService creates the connection and runs the transaction. inside the CustomerService code, the repository code is called. this ProductRepository has its own transaction. Before it creates a new transaction(new connection to the database) it checks whether it insides the a transaction and in this scenario, this is inside the transaction and so, the new transaction would not be created and the code will be executed in the same transaction.

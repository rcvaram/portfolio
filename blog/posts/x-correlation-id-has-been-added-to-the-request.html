X-Correlation-Id has been added to the request

Server requests concurrently one of the drawbacks that come with it is that it makes harder to trace what each request is doing, as it is doing it while other requests are doing other, often similar, things. That hurts logging information badly, as the messages generated for one request can easily be intermingled with other messages generated for other requests.

How can we trace a person we can put an identity on ther person and trace it. Same thing can be done for requests We can use the MDC(Mapped Diagnostic Context) of the Logback( log4j2 also provides this) as they mention MDC manages the contextual information per-thread basis. So when we set a key to thread we can track the thread what is doing.

MDC.put(key,value)

Here, We have to identify each request because filter out the logs based on request key and analyze what it is done.
The common best practice is giving an Id normally called as Correlation Id as a header of HTTP request.

Before sending the request to contrlller we have to filter out the header value add into the MDC of the logback

Vulanrablites

Initially, we sent responses without enveloped it but if we do like that we will get potential attacks, vulnerabilities. So we have enveloped with the data field.

How Data actually handled in Java?

There are two type of memory primarly used by Java. JVM manages these two memories. these two memoreis lies in RAM.

Each thread has its own stack. that’s why in the image, We have three threads t1,t2, t3 and all these threads has its own stacks.

But all threads share a common heap memory.

In stack each method will be in seperate blocks.

  1. Temporary variable
  2. Primitive Data types
  3. references of heap objects

When a variable within a SCOPE, then it will be visible once it is out of the SCOPE, it will be removed from the STACK in LIFO manner.

We need to understand that each variable can its ownscope for example if a variable defined inside a method it will be only valid and visible within the method and that is the SCOPE of that variable.

Java throws StackOverFlowError when the Stack memory gets full.


public class MemoryManagement {
    public void test() {
        int pointX = 10;
        int pointY = 10;
        Point p = new Point(pointX, pointY);
        Graph gr = new Graph();
        gr.addPoint(p);
        System.out.println("Graph is created");
    }
}

public class Graph {
    private final List<Point> points = new ArrayList<>();

    public void addPoint(Point point) {
        System.out.println("Point is received");
        points.add(point);
    }
    //Other methods...
}

public class Point {
    private int x;
    private int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
}

Lets think how these data is stored in memory.

Thread T1 is executing the test() method.

Since test() is currently active,its stack frame is present on the T1 stack.

We haven’t created any object yet in this diagram

For the first two lines → pointX and pointY are local variables belonging to the test() invocation.

Their values will be stored the current stack frame of T1.

No object has been instantiated yet that’s why Heap is still empty.

We now create a Point object using the new operator.

The Point instance is created in the heap, while the local variable p holds a reference to that object in the current test() stack frame.

gr is a local reference variable stored in the T1 stack frame.

The Graph object is allocated on the heap. The gr reference points to that object.

The Graph object contains a points field.

Since points is a reference type, the field itself doesn’t contain the collection data. It contains a reference to another heap object representing the collection.

In the next line gr.addPoint() is invoked by the thread t1.

The test() frame is still on the stack, but it is no longer the current frame.

When gr.addPoint(p) is invoked, the JVM creates a new addPoint() frame on the same thread’s stack.

The test() frame is paused until addPoint() returns.

The new frame(addPoint) receives the this reference pointing to the Graph object and the p parameter pointing to the existing Point object.

points.add(point) line will be executed.

points.add(point) does not copy the Point.

The list stores the reference value pointing to the existing heap object.

Therefore p, point, and the list element can all refer to the same Point instance.

Since gr.addPoint()method closing } is reached the t1 will remove the frames from the stack

Initially points.add() frame will be removed. then System.out.println frame which would be another method call frame is removed.

When point and this are removed from the stack relevent links to the objects also will be deleted.

frames will be removed LIFO manner.

The stack follows LIFO, the most recently pushed addPoint() frame is the first frame to be popped. After it returns, execution resumes in the test() frame

.T1 will back to test method place.

It will finish the System.out.println execution.

Now test method scope is completed and it is identified by } brace. so now in LIFO manner each frame will be removed from the stack.

Java uses a LIFO call stack removes each frame after execution is completed.

The heap objects are unaffected by the stack-frame removal.

The Graph and Point remain reachable through their references.”

Now it totally removed and back to the test method

The test() method has completed its stack frame is popped.

The heap objects are not destroyed as part of the method return.

They remain until they become unreachable and are subsequently reclaimed by the garbage collector.

Popping a stack frame does not immediately delete objects from the heap.

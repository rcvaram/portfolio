What If Cloud wasn’t a place to Sync, but a Place to Store?

CloudBind → A thin layer that turns cloud storage into something closer to a digital archive.

I recently bought a Google Pixel and also with 5 TB of Google storage for one year. My first thought was simple.

Great → More Storage

When I looked up at my laptop, my SSD was already full. I did not take thousand photos of yesterday. It was full of things I had accumulated over years.

  • Old Projects
  • Downloaded Files
  • Documents
  • Backups
  • Archives
  • Things I had not opened months.
  • Things I would not probably open for another six months.

However I didn’t want to delete any of them.

Read it here If you are blocked by paywall.

So I wondered…

If I already have 5 TB of cloud storage, why am I still keeping files I rarely use on my laptop?

Seems like a simple storage problem is that? No…

I thought about it more and I realized its more related to a file-management problem.

I didn’t wanna delete my files but also I want my local storage back as well.

Does this familiar to you?

You have a folder sitting on your computer that you haven’t opened for eight months.

You know you don’t need it today but you’re not ready to delete it.

It could be old project, university work or old phone backups.

We simply think → I might need this someday. File stays, stays and stays forever. and eventually we will end up to use a lot of local disk and we might have less than 5GB and we started to delete the things randomly or upgrading our SSD.

Most of us think, cloud is replication to Sync.

My computer ↔ Cloud

The cloud is another copy of my computer. That is incredibly useful. If I want to work on a document from my laptop and phone, synchronization makes sense.

If I want the same files on multiple devices, synchronization is exactly what I need it however what about the files I don’t need everywhere?

I don’t need synchronization and need somewhere to put things.

The setup

Instead of keeping the files inside my laptop I just wanna keep a pointer in few bytes and move the file into google drive but with encrypted way.

Why I choose encrypted version instead of plain version in cloud?

Cloud storage is convenient. but who controls my data? who has access?

So is it possible to make cloud storage convenient without giving up control over my data?

I started looking for a simple workflow

I looked at existing tools.

One tool that stood out was rclone. It can move data between my computer and many different cloud-storage providers.

For the actual transportation of files, it was exactly the kind of foundation I was looking for.

But I noticed something.

My problem was:

“How do I manage a file that is no longer on my computer but still belongs to me?”

Imagine I archive 5000 files. Six months later, I don’t want to remember:

  • Which files did I archive?
  • Where did they go?
  • Did they actually finish uploading?
  • Is the remote file the same file I originally had?
  • How do I bring it back?
  • What happens if something goes wrong?

I wanted my computer to remember that relationship for me not the entire file.actually the knowledge that the file exists and has been archived.

That was the idea that eventually became CloudBin.

What is actually my idea?

Which files need to live on my computer?

World 1
My laptop should contain the things I am actively working with.

World 2
My cloud storage can contain the things I wanna keep but don’t need every day.

With this CloudBin bridge, I can confidently say

“I don’t need this right now. Put it away.”

Later

“I need it again. Bring it back.”

CloudBin makes

  • No deleting.
  • No manually remembering remote paths.
  • No keeping the full local copy simply because you might need the file someday.
  • Archive with encryption.
  • Free the space.
  • Restore when needed.

Wanna try the idea?

CloudBin is still an early prototype, so I don’t want to pretend it is production-ready.

if the idea sounds useful, you can try it yourself.

The current prototype is available as a Python package and on GitHub.

pip install cloudbin

For now, there are a few important limitations:

  • Linux only — this is the environment I’ve tested it on.
  • rclone is currently used as the underlying storage layer.
  • Google Drive is the cloud provider I’ve tested with so far.
  • Please use non-critical files while experimenting with it.

The experiment is simple:

Pick something you haven’t used in months.

Archive it.

Free the space on your SSD.

Then restore it.

If the experience makes you think:

“Why wasn’t this how I managed old files before?”

then the idea might be onto something. if it doesn’t work for you, that’s equally valuable.

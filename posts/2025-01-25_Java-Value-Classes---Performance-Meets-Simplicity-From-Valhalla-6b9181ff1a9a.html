Java Value Classes → Performance Meets Simplicity From Valhalla

Project Valhalla introduces value classes in Java. Value classes boost performance. Value classes add primitive flexibility for objects. Developers can write more efficient, streamlined code.

Value Class?

Value classes are

  • lightweight,
  • immutable classes
  • without an identity.
Two instances with the same values are considered equal, and optimized for performance.

There are no object headers or pointers hence its efficient memory usage Therefore it is compact.

It acts like primitives hence its performance boost.

value class Point {
    private final double x;
    private final double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }
}

Point is just a flat simple one since it only has x and y. No need for extra memory.

Does it look like records?

Record

record Point(double x, double y) {}
//Auto-generates a constructor, equals(), hashCode(), and toString().
//Behaves like a lightweight, immutable data object.

Value class

value class Point {
    private final double x;
    private final double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }
}
//Requires explicit constructor and methods.
//No object identity; instances are stored and handled like primitives.

Similarities →

  • Both are aimed at representing immutable data.
  • Both reduced the boilerplate code.
  • Both focus on state-based equality.

Differences →

  • Records are used to create immutable data carrier objects but value classes aimed to see like classes but under the hood, they work as primitives.
  • Records still have an identity. values do not have an identity.
  • Records are regular objects with headers and references. value classes are scalirized. they are stored in memory no headers and no pointers.
  • Records require object allocation in the heap but value classes have no need for heap allocation
  • Records are Equals() was autogenerated however value classes rely on native equals ==
records are good for immutable object creation, value classes are good in optimizing performance by removing object identity and operating more like primitives.
Value class doesn't have any identity so when we compare with ==, they compare each fields value.

How Do Value Classes Improve Java?

JVM treatment

The JVM can see value classes as individual variables, avoiding object allocations and improving cache locality.

== usage

Value classes remove confusion between == (reference equality) and .equals() (state equality).

Point p1 = new Point(1.0, 2.0);
Point p2 = new Point(1.0, 2.0);
System.out.println(p1 == p2); // true

In generics point of view

Value classes work with generics without boxing overhead, unlike primitives.

List<int> numbers = new ArrayList<>(); // Not allowed

List<Integer> numbers = new ArrayList<>(); // Allowed, but incurs boxing overhead

This boxing introduces overhead, as it requires:

  1. Object creation: Wrapping the primitive in an object.
  2. Memory overhead: Allocating memory for the boxed object.
  3. Unboxing: Converting the boxed object back to a primitive during usage.

when value class is used with generics, it can be scalarized (treated as a collection of individual fields rather than full objects).

value class Point {
    private final double x;
    private final double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    public double distanceFromOrigin() {
        return Math.sqrt(x * x + y * y);
    }
}



public class Main {
    public static void main(String[] args) {
        List<Point> points = new ArrayList<>();
        points.add(new Point(3.0, 4.0));
        points.add(new Point(5.0, 12.0));

        for (Point p : points) {
            System.out.println("Distance: " + p.distanceFromOrigin());
        }
    }
}

The JVM optimizes Point by scalarizing it, treating the fields (x, y) as independent variables. This eliminates object allocation.

Value classes combine the abstraction of objects with the performance of primitives. By removing object identity and enabling scalarization, value classes optimize memory usage, improve cache locality, and reduce the overhead seen with traditional objects.

Take Aways

→ Value Classes = Lightweight, Identity-Free, Immutable: They behave like primitives but allow us to code as if working with classes.

→ Optimized Memory Usage: No headers or heap allocations; fields are stored directly in memory.

→ Comparison Made Simple: == for state equality, avoiding confusion with .equals().

→ Difference from Records: Value classes aimed for performance and primitive-like behaviour, while records are regular objects designed for simple, immutable data structures.

The first program we wrote in Java should have a main method — public static void main(String[] args)

We have been taught this is the entry point of the program from that point on wards.

But,

When you write a static block, you may see that it was executed before this main method so-called entry point.

The JVM’s Hidden Bootstrap Sequence

When you run java MyClass, the JVM doesn’t jump straight into main(). Instead,

1. class loading

The JVM’s ClassLoader locates Test.class, parses its bytecode, and populates the method area with class metadata.

During the preparation phase, static fields are assigned their default values (e.g., 0 for integers, null for objects).

Only during initialization are these fields assigned their declared values and static blocks are executed.

It prepares the class but doesn’t execute code yet.

2. Class Initialization (Static Blocks Live Place)

The JVM loads classes dynamically.

A class may not be loaded until its first reference (e.g., when accessed via new or Class.forName()). This behaviour allows Java applications to optimize memory usage and defer loading unused classes.

JVM initializes static variables and runs static blocks. This is governed by the Java Language Specification and triggered by:

  • First instance creation
  • First static method call (including main())
  • First static field access (if non-final)

3. Execution Phase

Only after initialization does the JVM runs main(), marking the start of your application’s logic.

public class Test{
    static { System.out.println("Static: setup"); }
    
    public static void main(String[] args) {
        System.out.println("main(): rise");
    }
}

// Output 
// Static: Backstage setup
// main(): Curtains rise

Static Blocks is not going to take away the importance of the main method

JVM Specification Enforcement

The JLS states that class initialization precedes any method invocation (§12.1.4).

Static blocks are part of this initialization and to ensure the class structural soundness before main() runs.

Without this guarantee,

main() might reference uninitialized static fields, leading to undefined behaviour.

2. The Entry Point Catch

The main() method isn’t the first code to run—it’s the first developer-defined code to run.

The JVM itself executes native initialization routines (like setting up the heap, thread system, and class loaders) long before your code even loads.

3. No Main() → No Execution

I ran this…

public class NoMain {
    static { System.out.println("I ran!"); }
}

I got this…

Error: Main method not found in class NoMain
If you put Static blocks only without main then the code will not run. The JVM exits if main() is missing, proving it’s the true entry point.

In Real world

Static blocks used to perform essential initialization tasks when a class is loaded.

For example, consider a scenario where a database driver pre-registers itself:

public class DatabaseDriver {
    static {
        try {
            DriverManager.registerDriver(new CustomDriver());
            System.out.println("Driver registered with SPI");
        } catch (Exception e) {
            throw new RuntimeException("Failed to register driver", e);
        }
    }
}

The static block ensures that the CustomDriver is registered with the DriverManager as soon as the DatabaseDriver class is loaded.

This approach is common in frameworks that use Java's Service Provider Interface (SPI).

Even if the the main() method never directly references the DatabaseDriver class, the JVM still loads it during provider discovery via the SPI.

Static blocks are suitable for tasks that must occur at the class-loading stage.

When Static Blocks Aren’t Enough

  • Final Static Variables
    The JVM may inline static final primitives/Strings at compile time, bypassing static blocks:

public class InlineDemo {
    static final String NAME = "Java";
    static { System.out.println("Never runs"); }
    
    public static void main(String[] args) {
        System.out.println(NAME); // No class initialization occurs
    }
}

static block never executes

Compile-time constants (e.g., static final String NAME = "Java";) are inlined at compile time and bypass class initialization.

However, if the static final variable is initialized with a non-constant expression (e.g., a method call or a dynamically computed value), the static block will execute.

  • Class Initialization Triggers
    Using Class.forName("MyClass", true, classLoader) initializes the class, while ClassLoader.loadClass("MyClass") only loads it without triggering initialization.

Before any user-defined code runs, the JVM initializes critical components like the garbage collector, JIT compiler, and thread management.

This native initialization ensures that the environment is ready for Java code.

By understanding the three-phase lifecycle (load → initialize → execute), you gain insights into:

  • How frameworks like Spring initialize before main() via SpringApplication.run()
  • Why dependency injection containers often initialize critical beans during static phases
  • The risks of blocking operations in static blocks (they stall the JVM’s startup sequence)
The JVM enforces the main() method's signature (public static void main(String[] args)) as the entry point for user-defined logic.
This convention ensures consistency but isn't technically tied to JVM initialization phases

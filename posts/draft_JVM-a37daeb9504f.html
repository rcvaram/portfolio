JVM

JVM main components are class loader, rutime data area [memory management] and execution engine

ClassLoader

Loading

Test.class — → to Test.class file

This class file will be loaded to memory by class loader. these class loaders are three types

bootstrap class loader, extension classloader and application classloader. Bootstrap classloader is the basic one which loads the classes from runtime jar. precompiled files will be loaded to memory.

Extension loader is the one used to load the file from /jre/lib/ext. External / third party dependencies will be loaded by this laoder. 

Application loader is used to load the class files to the memory area.


Linking phase

Linking can be done by verify, prepare and resolve. Once the class files are loaded to the memory. there is a verify phase where the bytecode class files are verified if they conform to standards. In preparation, memory is allocated for the static variables ad default values are assigned. Resolve phase all the symbolic references are replaced with actual references.


Initilization Phase

In the initlization phase of class loader component all the static variables are assigned with the actual values ad it also execute the static initializers at this point of time. 

Runtime memory data 

Method Area — ALl the class level data are stored in this memory area. 

Heap Area — All the objects ad instance variables are stored in this area

Stack Memory — Three sections Local variables, operand stack — containing the operands and frame data will be stored here. 

PC Register — Curret execution instruction

Native Method Stack -native method information 

Execution Engine

Interpreter — read the data and interpret the line by one 

JIT- when repeated method is called multiple times. JIT complies the bytecode to native code. this native code will be used directly for repeated method calls. JIT compile contains few components to achieve this feature. 

  • intermediate code generator — generates the intermediate code
  • code optimizer — Optimizes the intermediate code for better performance 
  • Target code generator — Converts intermediate code to native machine code
  • Profiler — It is response for finding the hotspots, methods which are called repeatedly 


Garbage collector

GC is responsible for destroying the old unused objects.

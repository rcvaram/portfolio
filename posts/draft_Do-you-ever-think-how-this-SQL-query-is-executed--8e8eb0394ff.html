Do you ever think how this SQL query is executed?

This Query processing is just a 3 steps procedure

  • Parsing and Translation
  • Optimization
  • Evaluation

When a query is written in SQL language Its look like below

Select student_name 
From students
where age < 10
// This simple query will retrieve the student's names // who are less than age of 10 in students database.

Parsing and Translation

We need to check the SQL query syntax and its relations. We use the parser to do these checkings.

We need to translate the SQL query into relational algebra since it provides a theoretical foundation. However, we do this translation in two steps.

  • The SQL query is translated to internal form
  • The internal form is translated to relational algebra notations

The problem is, a relational algebra expression may have many equivalent expressions.

For our SQL query, we can write below relational algebra expressions. 

σ age < 10 (∏ student_name (students))

Or 

∏ student_name (σ age < 10 (students))

We need to choose the expression that can be used to query the database. Basically, we need to find low-cost expression among all expressions is nothing but query optimization. Here, we refer total elapsed time for answering a query as cost.

Query Optimization

This is a broader topic, I will do a blog for this don’t worry guys !!!. For now, I will give an abstract view of what we do in query optimization

  • We measure query costs
  • We use algorithms to evaluate relational algebra expressions, Based on the evaluation, we find the best combinations of expression. 
  • We will find an evaluation plan with the lowest estimated cost

This evaluation plan is given to the DB engine.

Evaluation

The query-execution engine takes a query-evaluation plan, executes
that plan, and returns the answers to the query.

Evaluation plan

It is an annotated expression for DB engine to execute the query with detailed specification

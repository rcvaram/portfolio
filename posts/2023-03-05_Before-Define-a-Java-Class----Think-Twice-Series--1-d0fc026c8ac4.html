Before Define a Java Class — Think Twice Series -1

The best practices in Java.

As a Java developer, you hold the power to create incredible software applications by defining classes. A class serves as the foundation for creating objects and is essential to building software that’s maintainable and scalable. By following best practices when defining classes, you can create code that’s easy to read, maintain, and extend.

So, get ready to suit up and dive into some of the best practices to follow when defining classes in Java. We’ll show you how to make your classes super-readable with clear and consistent naming conventions, how to use access modifiers to keep your code safe and secure, and much more. Let’s get started!

So,

Think Twice before define a class

1. Use meaningful names for classes

Use names that accurately describe what the class does, and use standard naming conventions.

Some Naming Conventions that are used commonly

  1. Java class names should be written in PascalCase, which means the first letter of each word should be capitalized. ex — PersonInfo.
  2. Use nouns or noun phrases: Class names should generally be nouns or noun phrases that describe the objects or concepts that the class represents. ex — Person
  3. Avoid abbreviations: Avoid using abbreviations or acronyms in class names, unless the abbreviation is well-known and widely used. For example, HTTPServer is a well-known and widely used abbreviation, but BankMgr is not.
  4. Use singular nouns for non-collection classes: For classes that represent a single object or entity, use a singular noun. ex — Person instead of Persons
  5. Use plural nouns for collection classes: For classes that represent a collection of objects or entities, use a plural noun. ex — Persons instead of PersonList
// Bad example: unclear class name
public class XYZ { /* ... */ }

// Good example: clear class name
public class Customer { /* ... */ }

2. Keep classes small and focused

Try to keep classes small and focused on a specific task. This makes it easier to understand and modify the code.

// Bad example: a class that does too much
public class SalesReport {
    public void generateReport() {
        // a long and complex method that generates a sales report
    }
}

// Good example: a class that has a specific purpose
public class SalesReportGenerator {
    public void generateSalesReport() {
        // a short and focused method that generates a sales report
    }
}

3. Use access modifiers to control visibility

Use access modifiers (public, protected, and private) to control the visibility of class members. This helps to prevent unintended changes to the code.

  1. Public: A public class, method, or variable can be accessed from anywhere in the program, including from other packages.
  2. Private: A private class, method, or variable can only be accessed within the same class. It is not visible to other classes in the same package or in other packages.
  3. Protected: A protected method or variable can be accessed within the same class, within any subclass of that class, and within any other class in the same package.
  4. Default (no access modifier): If no access modifier is specified, the class, method, or variable can be accessed within the same package but not from other packages.
// Bad example: public field that can be accessed and modified from anywhere
public class Person {
    public String name;
}
// Good example: private field with getter and setter methods
public class Person {
    private String name;
    public String getName() {
        return name;
    }
    public void setName(String name) {
        this.name = name;
    }
}

4. Minimize coupling and maximize cohesion

Minimize the dependencies between classes and maximize the coherence of the code within each class. This makes the code easier to maintain and modify.

// Bad example: a class that depends on another class too much
public class CustomerService {
    private DatabaseConnector dbConnector = new DatabaseConnector();
    
    public void saveCustomer(Customer customer) {
        dbConnector.connect();
        dbConnector.insert(customer);
        dbConnector.disconnect();
    }
}
// Good example: a class that has low coupling and high cohesion
public class Customer {
    private String name;
    private String email;
    public void save() {
        // code to save the customer to the database
    }
}

5. Follow the Single Responsibility Principle (SRP)

Each class should have a single responsibility or purpose. If a class has multiple responsibilities, it can become difficult to understand and maintain.

//example: a class that has multiple responsibilities
public class User {
    public void login() { /* ... */ }
    public void register() { /* ... */ }
    public void deleteUser() { /* ... */ }
}

//example: separate classes for each responsibility
public class UserAuthenticator {
    public void login() { /* ... */ }
}

public class UserManager {
    public void registerUser() { /* ... */ }
    public void deleteUser() { /* ... */ }
}

6. Use interfaces to define contracts

Use interfaces to define the contracts between classes, rather than using concrete classes directly. This makes the code more flexible and adaptable.

// Bad example: a class that depends on a concrete class directly
public class CustomerService {
    private DatabaseConnector dbConnector = new MySQLConnector();

    // ...
}

// Good example: a class that depends on an interface
public class CustomerService {
    private DatabaseConnector dbConnector;

    public CustomerService(DatabaseConnector dbConnector) {
        this.dbConnector = dbConnector;
    }

    // ...
}

7. Use composition over inheritance

Prefer composition over inheritance, as it makes the code more flexible and easier to modify.

// Bad example: a class that uses inheritance excessively
public class Car extends Vehicle {
    // ...
}

// Good example: a class that uses composition instead of inheritance
public class Car {
    private Engine engine;
    private Wheels wheels;

    // ...
}

8. Use static methods sparingly

Use static methods sparingly, as they can make code harder to test and maintain.

// Bad example: a class that uses static methods excessively
public class StringUtils {
    public static boolean isNullOrEmpty(String str) {
        return str == null || str.isEmpty();
    }

9. Use immutable classes when possible

Immutable classes are classes whose instances cannot be modified once they are created. Using immutable classes can make your code more reliable and easier to reason about.

public final class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int getX() {
        return x;
    }

    public int getY() {
        return y;
    }
}

10. Use factory methods instead of constructors

Factory methods are methods that create and return instances of a class. Using factory methods instead of constructors can make your code more flexible and easier to test.

public class Person{
    private Person() { /* private constructor */ }

    public static Person create() {
        return new Person();
    }
}

11. Avoid using public fields

Using public fields can make your code harder to maintain and reason about. Instead, use private fields with getter and setter methods.

public class Person {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

12. Use annotations to add metadata

Annotations are a way to add metadata to your code. Use annotations to provide additional information about your classes and methods.

@Deprecated
public class Person { /* ... */ }

13. Use the Builder pattern for complex object creation

The Builder pattern is a design pattern that allows you to create complex objects step by step. Using the Builder pattern can make your code more flexible and easier to understand.

public class Person {
    private final String name;
    private final int age;
    private final String address;
    private final String email;

    private Person(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
        this.address = builder.address;
        this.email = builder.email;
    }

    public static class Builder {
        private String name;
        private int age;
        private String address;
        private String email;

        public Builder setName(String name) {
            this.name = name;
            return this;
        }

        public Builder setAge(int age) {
            this.age = age;
            return this;
        }

        public Builder setAddress(String address) {
            this.address = address;
            return this;
        }

        public Builder setEmail(String email) {
            this.email = email;
            return this;
        }

        public Person build() {
            return new Person(this);
        }
    }
}

14. Avoid using inner classes

Inner classes are classes that are defined inside another class. Using inner classes can make your code harder to understand and maintain. Instead, use static nested classes or separate classes.

in Java, there are three types of nested classes: inner classes, static nested classes, and local classes. Inner classes are classes that are defined inside another class, whereas static nested classes are classes that are defined inside another class but are static. Local classes are classes that are defined inside a method.

Inner classes have access to the members of the enclosing class, which can make them useful for implementing certain types of behaviour. However, using inner classes can also make your code harder to understand and maintain, because the nested class is tightly coupled to the enclosing class. In contrast, static nested classes are not tied to an instance of the enclosing class and can be used in a more standalone fashion. They can still access the members of the enclosing class if they are static, but they do not have access to non-static members.

//Bad Example
public class Person{
    private int age;

    public class Box{
        public void open() {
            if(age>10){
              System.out.println( "chocolates");
            }else{
              System.out.println("Books");
            }
        }
    }
}

//Good example
public class Person{
    private int age;

    public static class Box{
       public void open(Person person) {
            if(person.age>10){
              System.out.println( "chocolates");
            }else{
              System.out.println("Books");
            }
        }
    }
}

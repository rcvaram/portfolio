How I prepared For My Senior Interview Q&A

  1. What is OOP?
    OOP is object oriented programming that organises software around objects where each object encapsulates data and behaviour
  2. What are the four pillars of OOP?
    Abstraction, encapsulation, polymorphism and Inheritance.
  3. Difference between Abstaction and Encapusation?
    Abstraction focuses on exposing only the essential behavior while hiding the implementation details. Encapsulation protects an object’s state controlling how it is accessed and modified ensuring the object remains valid. 
    Abstraction simplifies usage and, Encapsulation protects the integrity. 
  4. What is difference between interface and Abstraction?
    Abstraction focuses on exposing only essential behaviours while hiding the implementation details. Interfaces are contracts to define the class behaviours and interfaces are one of the way to use Abstraction and there are otherways such as abstraction class and well defined APIs.
  5. What is the difference between Abstract Class vs Interface?
    Interface defines the contract but abstract calls defines partial implementation. 
    Supports multiple inheritance but abstract class upports single inheritance. 
    interface represents “can do” capacity but abstract class represens is a relationship with shared behaviour. 
    interface promotes loose coupling but abstraction is more tightly coupling due to inheritance. 
  6. When would you choose Abstract Class?
    I would choose abstract class when multiple classes share common state and behaviour and I want avoid duplicating the code. If I wanna define contract only and allow unrelated implementation for different classes then I prefer interface. Interface provides flexibility and loose coupling.
  7. What is encapsulation?
    Encapsulation protects the object states controlling how it is accessed and modified ensuring the object remains valid. 
  8. How does encapsulation improves the maintainability?
  9. Can Immutable classes improve Encapusaltion?
    Immutable class means once the object is created, it fields can not be changed. This prevents accidental changes, make objects easier to reason about and improves thread safety. 
  10. What is inheritance?
    Inheritance represents “is a” relationship where a sub class inherits parent calls states and behaviours. while it enables code reuse, its primarly purpose is specialization and model the hierarchical relationships.
  11. when should inheritance be used?
    I use inheritance only when there is a genuine ‘is-a’ relationship and the child can be substituted for the parent
  12. Disadvantages of inheritance?
    Tight coupling
    Changes in the parent can affect all children.
    Can lead to fragile hierarchies.
    Less flexible than composition.
    can violate encapsulation if sub classes depend too much on parent implementation.
  13. Why composition over inheritance?
    Composition is preferred because it promotes loose coupling and greater flexibility. Objects collaborate instead of inherting behaviour. This makes it easier to replace implementations, test components independently and avoid deep inheritance hierarchy.  
  14. “has a” vs “is a”?
    “has a” delegates the work to another object instead of inheriting the behavior.
  15. What is polymorphism?
    It allows code to interact with different implementations through the same interface without depending on concrete class. 
  16. Compile time vs runtime polymorphism?
    Method overloading and this is resolved in compile time. Method ovveriding is runtime polymoprhism and this polymorphism decided based on dynamic dispatch of the actual object.
  17. What is Composition?
    Composition is “has a relationship” where one object contains another object and delegate the responsibilities to that object. 
  18. Aggregation
    Aggregation is weak “has a relationship”. the contained object can have independent life cycle and it can live without owning object. Department-> Employee.
  19. Association
    Where one object knows or use another object. It can be one way or two way relationship
  20. Dependency
    One object temporarily uses another object. for example, you use an object in the method call so in that case only when the method is called then the caller object temporarily uses the object 
  21. Dependency vs Association
    Dependency is temporary. Association is something referenced in the object. Association means has-a relationship. dependency is uses in method.
  22. Coupling means something that how much dependency both objects have.

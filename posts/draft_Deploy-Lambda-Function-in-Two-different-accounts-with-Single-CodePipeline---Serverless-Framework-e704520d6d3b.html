Deploy Lambda Function in Two different accounts with Single CodePipeline & Serverless Framework

Scenario → I faced a situation where I have to deploy the lambda function for the non Prod and Prod accounts with the same codepipeline. and additionally, I have to use only one deployment bucket for an account.

By Default, the Serverless framework will create a bucket for each environment which leads to many old deployment buckets laying around in your AWS account.

To overcome this, we used the serverless-deployment-bucket plugin to create a single bucket and within the bucket, environments were added as folders. This plugin will create your custom deployment bucket if it doesn’t exist, and optionally configure the deployment bucket to apply server-side encryption.

Create code pipeline in non-prod account with single S3 bucket as deployment bucket


Codepipeline CFT Template

We used Github as a source to trigger the pipeline. 


Serverless Yaml File

service: test-service
plugins:
  - serverless-deployment-bucket
provider:
  name: aws
  runtime: java11
  timeout: 600
  role: TestServiceRole
  stackTags: ${file(tags.yaml)}
  deploymentBucket:
    name: test-depl-bucket
    versioning: true
    blockPublicAccess: true
  vpc:
    securityGroupIds:
      - !Ref TestServiceSecurityGroup
    subnetIds:
      - your vpc subnet Id
  environment:
    STAGE: ${opt:stage}
resources:
  - ${file(resources.yaml)}

package:
  artifact: target/test-service-0.0.1-SNAPSHOT-aws.jar

functions:
  test:
    handler: org.springframework.cloud.function.adapter.aws.FunctionInvoker::handleRequest

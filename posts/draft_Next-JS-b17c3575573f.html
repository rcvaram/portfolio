Rendering

Client Side Rendering

  • Large bundles
  • Resource intensive
  • Less Secure
  • NO SEO

Server Side Rendering (SSR)

  • Smaller bundles
  • Resource Efficient
  • SEO
  • More Secure

Server components

Interactive will be lost

cons

  • Unable to listen to browser events : [click, change, submit]
  • Unable to access browser APIs [local storage]
  • Unable to maintain a state / use effects.
Use Server Components as default and use Client Components when it is needed only

In NextJS Whatever we create inside the app directory are server components. If we do not add the page.tsx then the folder inside the app directory will not be accessible publically.

Components will not be accessed publically however users and users/new will be accessed publically.


I added an onClick interactive event for a server component then this is not going to work

import React from 'react'
const ProductCard = () => {
    return (
        <div><h1>ProductCard</h1>
            <button onClick={() => console.log("button clicked")}> Add to Cart
            </button></div>
    )
}
export default ProductCard

The browser will display the error as a runtime error as below

Now we understood that the server components cannot be used interactively, so we need to convert them into client components.

We can add this entire ProductCard component to a client component

use client at the top. With this change, we requested nextJS to treat it as a client component.

'use client';
import React from 'react'
const ProductCard = () => {
    return (
        <div><h1>ProductCard</h1>
            <button onClick={() => console.log("button clicked")}> Add to Cart
            </button></div>
    )
}
export default ProductCard

The Error was gone.


The better approach is to create a component specifically for client interaction, rather than moving everything to the client component.

New Component — AddToCart

"use client";
import React from "react";
function AddToCart() {
  return (
    <button onClick={() => console.log("button clicked")}> Add to Cart </button>
  );
}
export default AddToCart;


Inject AddToCart Component to ProductCard Component

import React from "react";
import AddToCart from "./AddToCart";
const ProductCard = () => {
  return (
    <div>
      <h1>ProductCard</h1>
      <AddToCart />
    </div>
  );
};
export default ProductCard;



Fetching Data


We can fetch data in two ways.

client-side fetching typically involves useState+useEffect. useState hook to store the value in a state and use effect hook to retrieve the data from the back-end and put it into the defined state. Instead of useState+useEffect, you can use react query as well.

However, fetching from the client side will cause many problems as you now large bundle, resource intensive, no SEO, less secure and extra roundtrip to the server.



Rendering

Static Rendering

If we have static data in our application, then we can render the data once and then we build a production application. 

Dynamic Rendering

This is happening for each request.

Rendering -> Client Side Rendering
          -> Server Side Rendering
                                  -> Static Rendering { Runs on build time}
                                  -> Dynamic Rendering {Runs per request}

Note on SOLID

S → Single Responsibility Principle

Every class must perform a single functionality.

Implementation of multiple functionalities in a single class mashup the code.

O → Open & Close Principle

Open for Extension & Closed for Modification

The open-closed principle states that according to new requirements the module should be open for extension but closed for modification.

L → Liskov Substitution Principle

Parent class can be replaced by the child class without interrupting the flow

Derived classes must be completely substitutable for their base classes which means A program design should not be interrupted by child class substitution for the parent class.

I → Interface Segregation Principle (ISP)

A class should not be forced to implement methods which are irrelevant to them.

We need to define interfaces in a way that only needed methods should be in the interface. Keep your interfaces the smallest as you can

D → Dependency Inversion principle

High-level modules should not depend on low-level modules but both should depend on the abstraction

Objects should not instantiate their dependencies, but they should be passed to them.

JWT With Spring Boot

JWT is a popular way to do user authorization in web apps today. Here, we will see how can we use the JWT in the spring boot to secure our application.

For that, we want to know really what is JWT?

The open industry standard specification called the RFC 7519 which outlines how a JWT ability should be structured and how to use it for exchanging information. 

The difficulty in web communication is the HTTP protocol. Why? HTTP is a stateless protocol. every interaction of the HTTP needs to contain all the information needed for that interaction. Nothing is remembered from the previous interaction. NO information is saved or the state is saved in HTTP protocol. How the session is maintained on the website? there are two ways to maintain the user sessions. The first one is session tokens and JSON web token.

Session token

When you authenticate to the server, the server will create the session and keeps track the user session. each session has id, that will be unique for user. This id will pass from the user and server checks with stored session information which is in server. The normally the session id is saved in a cookie. It automatically gets added to the cookie header on every subsequent request. Authentication happens, the server saves the state and returns a response, for the cookie sub subsequent requests from the browser automatically have the cookie at the header. so the server looks up the cookie header to identify the user easily. This mechanism saving session ID as token and saved in cookies has been fine but here we have some problems. Here, we assumed only one server but in reality, we may have multiple servers and a load balancer. In this case, the load balancer may route different servers when the request comes from the same client. For that, we have to manage sessions. one is a sticky session and the other one is sharing the session with all servers using common session management.

The Case of the Duplicate Spring Beans: When IntelliJ Outsmarts You

You deleted the class, cleaned the build, invalidated caches… and still Intellij throws an error saying you have a duplicated bean.” — Read this to fix it

Issue

I was working on a Spring Boot project and blocked by a runtime error . My application failed to start with this dreaded message:

Parameter 0 of method openAPIBuilder in org.springdoc.core.configuration.SpringDocConfiguration 
required a single bean, but 2 were found:
- customOpenAPI: defined by method 'customOpenAPI' in class path resource [.../OpenApiConfig.class]
- myOpenAPI: defined by method 'myOpenAPI' in class path resource [.../SwaggerConfig.class]

This didn’t make sense.

I had already deleted one of the classes and kept only the correct one OpenApiConfig.

My project directory was clean.

I verified again: only one config class existed in src/main/java. So from where is this second bean coming from?

My Trials and Errors

I went through the usual tries:

  • ✅ Ran ./gradlew clean build
  • ✅ Invalidate and restart caches in IntelliJ
  • ✅ Manually cleaned the build/ folder
  • ✅ Verified the build/ and .idea/ folders

Everything looks good even build folder doesn’t have two beans

Still, Spring Boot continued to complain about two beans.

I take a moment to pause. Instead of doing trial and error, I try to identify the actual problem. Okay, the same code works in the cloud, so there must be an issue with my machine. What does that mean? It means I have a problem with my IntelliJ IDE. I tried cleaning caches but still face the same issue.

IntelliJ’s out/ Folder

IntelliJ maintains its own build output directory, and it’s not build/

I checked the out/ folder in my project root (usually /out/production/classes/ or similar).

And there it was—both old and new class files sitting quietly together like nothing had happened.

That stale .class file from the deleted config class was still being picked up by the application at runtime.

So even though it was gone from the source, it was very much alive in IntelliJ’s output.

✅ The Fix

Here’s what worked for me:

  1. Delete the out/ folder manually.
  2. Rebuild the project from scratch.
  3. Restart IntelliJ if needed.

Once I did that, the issue disappeared and the application ran perfectly.

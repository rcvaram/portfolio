The Code to Guess 🎲

interface Sneaky {
  default void surprise() {
    System.out.println("Sneaky says: Boo!");
  }
}

interface Tricky {
  default void surprise() {
    System.out.println("Tricky says: Gotcha!");
  }
}

class Puzzle implements Sneaky, Tricky {
  // No override here—uh-oh?
}

public class Main {
  public static void main(String[] args) {
    Puzzle p = new Puzzle();
    p.surprise();
  }
}
Does it print “Boo!”🤔?
Does it print “Gotcha!”?
Does it just blow up? 🤯

Think fast, then let’s unravel it together!

Step 1: The Interface Showdown 👀

  • Sneaky has a default method surprise() that says “Boo!”
  • Tricky has its own default method surprise() that says “Gotcha!”
  • Puzzle implements both interfaces. No override, no nothing!

Default methods give interfaces pre-made code. But what happens when two interfaces bring the same method to the party?

Step 2: The breakdown

  • When Puzzle inherits surprise() from both Sneaky and Tricky, the compiler freaks out. It’s like, “Yo, which one do I use? Boo or Gotcha?!”
  • Without an override in,Puzzle Java says, — "No,I’m not guessing for you!”
No “Boo!”, no “Gotcha!”, just a big fat compile-time fail.
  • Default methods are a way for adding behavior to interfaces without breaking old code.
  • But if a class implements two interfaces with clashing default methods (same name, same signature), Java asks you step in and resolve it.
  • You’d need to override surprise() in Puzzle like this
class Puzzle implements Sneaky, Tricky {
    @Override
    public void surprise() {
        Sneaky.super.surprise(); // Picks "Boo!"
        // Or Tricky.super.surprise(); for "Gotcha!"
        // Or your own custom message!
    }
}
Without that, it’s game over at compile time. Sneaky, sneaky Java!

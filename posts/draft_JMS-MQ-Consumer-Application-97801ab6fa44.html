JMS Session

A JMS Session can be looked as a place for the listener thread to communicate with JMS Provider connection. JMS Session is a single thread context hence if we have multiple threads then we have multiple sessions. A JMS Session can not be have multiple threads but a thread can have multiple sessions.

The acknowledgment will be happen by commit when the session is truncated. otherwise user can give the ack mode. And Recovery is handled by rollBack. 

To consume messages from MQ, we need a message listener container of jms. Message Listener Container and JMS template are the key components of Spring JMS. Here, the JMS Template is used to receive or send messages synchronously. The Message listener container can be used to send messages asynchronously. Spring doesn’t provide the JMS. You need to configure the external JMS Provider(ActiveMQ, JBoss Messaging, IBM WebSphere MQ). 

The purpose of the JMS template and the message listener container is to isolate the developer from the details of connecting to the JMS provider, establishing a JMS connection, creating a JMS session, and creating a JMS message producer or message consumer.

We need to have a non-blocking process that can listen for the messages from the particular queue which means the presence of the message will trigger an action of the listener. 

Spring provides three-way to implement the message listener. All three of these methods use a message listener container. 

  1. Java.jms.messageListener
  2. SpringSessionAwareMessageListener
  3. A Standard POJO in Spring’s MessageListenerAdapter Class

Message-Driven POJOs are created within the context of the message listener container. connectionFactory, jmsDestination and messageListenerBean are bonded to this message Listener Container. 

  1. DefaultMessageListenerContainer
  2. SimpleMessageListenerContainer

While both of these message listener containers allow you to specify the number of concurrent listener threads, only the DefaultMessageListener Container has the ability to dynamically adjust the number of listener threads during runtime.

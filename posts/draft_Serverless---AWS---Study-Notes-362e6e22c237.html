Serverless | AWS | Study Notes


Serverless is a new paradigm in which the developers don't have to manage servers anymore. 

Deploying the code is enough to run the application.

Serverless Example

  • Users can get static content from the S3 bucket.
  • Users can log in with the help of Cognito (Users would have their identity stored).
  • Users would invoke the REST API through API Gateway to Lambda function.
  • The Lambda function will call Dynamo DB to get the data and the lambda function will go back to the user with the data.

AWS Lambda

  • Virtual functions — no servers to manage
  • Limited by time — short executions (around 15 minutes)
  • Run on-demand
  • Scaling is automated

Lamda Advantages

  • Easy pricing (Pay/request & compute time)
  • Integrated with many languages (NodeJS, Python, Java, C#, Golang, Ruby, Custom Runtime API)
  • Easy monitoring through AWS Cloud watch
  • Easy to get more resources/functions 
  • Increasing RAM will also improve the CPU & network.

Limitations

  1. Execution Limits
  • Memory Allocation : 128MB : 10GB (1MB Increments)
  • Maximum execution time: 900 seconds
  • Environment variables (4KB)
  • Disk capacity in the function container: 512 MB
  • Concurrency execution : 1000 

2. Deployment Limits

  • Deployment Size: 50 MB (Compressed) & 250 MB uncompressed 
  • /tmp directory to load other files at startup
  • Size of environment variables: 4KB

Amazon DynamoDB

  • Fully managed, highly available with replication across multiple AZs
  • NOSQL Database — not a relation database
  • Scales to massive workloads, distributed database
  • Millions of requests/seconds, trillions of rows and 100s of TB of storage.
  • Fast & Consistent in performance
  • Integrated with IAM for security, authorization & administration
  • Enables event-driven programming with DynamoDB Streams. 
  • DynamoDB is made of Tables (Don't need to create schemas)
  • Each table has a primary key & It should be decided at creation time.
  • Each table can have an infinite number of items. 
  • The maximum size of an item is 400KB
  • Data Types → Scalar Types (String, Number Binary, Boolean, Null), Document Types (List, Map) & Set types (String set, Number set, Binary Set)

Read / Write Capacity Modes

Control how you manage your table’s capacity (read/write throughput)

  1. Provisioned Mode (Default) → 
    * Specify the number of reads/writes per second.
    * Need to plan capacity beforehand.
    * Pay for provisioned read capacity units & write capacity units.
    * Possibility to add an auto-scaling mode for RCU & WCU
  2. On-Demand Mode →
    * Read & Writes automatically scale up / down with your workloads.
    * No capacity planning is needed 
    * Pay for what you use, more expensive 
    * Great for unpredictable loads

Dynamo DB Accelarator

  • Fully-managed, highly available, seamless in-memory cache for DynamoDB
  • Help solve read congestion by caching
  • Microseconds latency for cached data
  • Doesn't require an application logic modification (compatible with existing DynamoDB APIs)
  • TTL — 5 minutes

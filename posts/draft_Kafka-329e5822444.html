Kafka

You know guys, change is the thing that will not change forever which means most of the things change their states and because of this, they produce events. events are simply what happens on a particular thing state.

For Example, room temperature increased is an event and here the state of the room temperature changes. So you know that there are a lot of events. Is it possible to collect them or store them or process them. Yeah, that is possible and that's where the event streaming platform comes. We have a lot of event streaming platforms kafka, kinesis, google pub/sub and other platforms.

Today we will look at this Kafka event streaming platform.

Basically, We are looking at the Apache Kafka

We have a requirement to collect, store and process the events For this we need to categorize or organise the events right. Here the topics come to play. It seems like a table in the database where we can organise the events for a particular topic.

First, they are append-only: When you write a new message into a log, it always goes on the end. Second, they can only be read by seeking an arbitrary offset in the log, then by scanning sequential log entries.

Events are immutable. 

 Third, events in the log are immutable — once something has happened, it is exceedingly difficult to make it un-happen. The simple semantics of a log makes it feasible for Kafka to deliver high levels of sustained throughput in and out of topics, and also make it easier to reason about the replication of topics, which we’ll cover more later.

Logs are also fundamentally durable things. Traditional enterprise messaging systems have topics and queues, which store messages temporarily to buffer them between source and destination.

Event stored as key-value pair and these events are immutable because of that, we can achieve a lot of things. 

Kafka is a distributed system. If we have to put a lot of events on one topic and if it lives in one machine it makes it difficult to scale. So here comes up partitions, we created partitions for the topic. We can partition the topic to live in different Kafka clusters node. Wow Nice but how these messages are written to different partitions is not much hard to understand. I already told event is just key value pair. we use this key and hash it doing simple algo to select which partition it is needed to save if the key is not given for an event then it takes round robin setup to store the event in partition.

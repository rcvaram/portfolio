Is Java PASS-BY-REFERENCE?

Primitives → Passed by value (copy of the value). Objects → Passed by value (copy of the reference)

What is Pass-by-Reference?

  • You send a reference (memory address) to the method.
  • If the method changes the value, it modifies the original variable.
c++ code
#include <iostream>
using namespace std;

void modifyNumber(int &x) { // x is passed by reference.
    x = 10;  // Changes original value
}

int main() {
    int a = 5;
    modifyNumber(a);
    cout << a << endl;  // Output: 10
    return 0;
}

What is Pass-by-Value?

  • Pass-by-value means Java sends a copy of the value to a method.
  • If you change the value inside the method, the original value doesn’t change.

Which Java Uses?

SPOILER ALERT! Java is always pass-by-value

Passing Primitive Types (int, double, etc.)

public class Main{
public static void main(String[] args) {
    int a = 5;
    modifyNumber(a);
    System.out.println(a); // Output: 5
}

public static void modifyNumber(int x) {
    x = 10; // Changes only the copy
}}
Yeah Understandable : Java is pass-by-value

Wait! What about Passing Objects

  • When you pass objects in Java, you pass a copy of the reference.
  • Whatever changes to the object’s properties affect the original object.
class Person {
    String name;
}

public static void main(String[] args) {
    Person p = new Person();
    p.name = "Siva";
    changeName(p);
    System.out.println(p.name); // Output: Ram
}

public static void changeName(Person p) {
    p.name = "Ram"; // Changes original object's property
}

What does that mean? you pass-by-reference no way… If you assign a new object, it doesn’t change the original.

public static void changeReference(Person p) {
    p = new Person(); // New object
    p.name = "Raja"; // This change is not reflected original P 
}

Original p.name stays "Siva". So, Properties change, but if you assign a new object, it won’t affect the original.

dive deep …
  • When you pass an object to a method, you pass a copy of the reference (the memory address where the object is stored).
  • This means the method has a reference to the same object in memory.
  • When you modify the object’s properties (like changing a name), you’re changing the same object that the original reference points to.
If you see in the above example, p points to the original Person object. changeName() gets a copy of the reference to the same object. Changing p.name modifies the original object because both references point to the same memory location.
public static void changeReference(Person p) {
    p = new Person(); // New object
    p.name = "Raja"; // This change is not reflected original P 
}

If you assign a new object to the reference inside the method, the original reference remains unchanged. This is because the reference itself is passed by value.

Why doesn’t it change the original?

  • p inside changeReference() is a copy of the original reference.
  • Reassigning p to a new object only changes the local copy, not the original reference.
It looks like pass-by-reference because changes to the object’s properties reflect in the original object.
But remember,
Java passes copies of references, not the original reference itself.

Finally, in JAVA!

  1. Primitive Types: You pass a value, changes affect only the copy.
  2. Objects: You pass a reference to the same object, so changes to the object affect the original. But if you assign a new object to the reference, the original remains unaffected because the reference itself is passed by value.

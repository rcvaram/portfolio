Testing can only show the presence of failure, not the absences?

The purpose of testing is to check whether the software is doing what it is intended to do and whether there are failures in its functionalities. But with this, we are actually looking for the failures which are present and not the ones which are absent.

Sometimes the absence of failures is not important, but as the system grows, the absence of failures could emerge from the system, causing huge damage.

Necessary conditions to observe a failure

Reachability → the location or locations in the program that has the fault must be reached

Infection → the state of the program is incorrect due to fault

Propagation →The infected state will cause the final output or the results of the system to be incorrect.

Can we use the same set of employees for all test activities?

Criteria Based:
This requires a traditional CS degree
This is the most technical job in software testing
This requires knowledge of discrete maths, programming and testing

Human-based:
This does not require a traditional CS degree.
Requires the knowledge of Domain, user interfaces and testing
Having background knowledge in the domain, empirical background and logic background is helpful

No, we cannot. Test designers are mainly to do the technicalities of the test design. Human-based includes domain specialists who will understand the core testing needs, according to the context of the software. The domain specialists do not have an idea of programming, and programmers do not know much about the domain, Hence, cannot use the same set of people for both.


Describe the following things

Coverage Criteria: this gives a structured approach to search the input space thoroughly and ensure there is no overlap in tests. It tells you how much of the test inputs should be covered. Or how much of the original artefacts should be covered in testing.

Test evaluation is the final test activity. we have to evaluate the results of the testing and report back to the developers. This involves analyzing the test results, with the test cases and giving a report as to whether the tests have passed or not, and other relevant details.

Modern driven test design Software that we see today is complex. It makes testing very complicated. So we developed an abstract structure like a model, for the system, and then use this model for testing. This is model-driven test design. Based on the model we have abstracted out from the system, we carry out the testing and the designing.

Integration testing

integration testing is what needs to be carried out. Each of these components needs to be tested with proper interactions. These components provide interfaces for us to interact with them. There are three possible errors when interacting with component interfaces

1) Interface Misuse
2) Interface Misunderstanding
3) Timing Errors

Therefore we need to carry out proper testing and identify what happens within these components. First thing is to check whether we are misusing the interfaces. then whether we have misud=nderstood them. Then check for timing errors. and figure out what's wrong.


Regression testing

This suggests that the regression test has failed. When we make a modification, it should not affect the previous built system. If there is a change, it should be consistent with the previous work, where pth test and p+1th test results should match.

3 Reasons

1) Software has a fault — the change that we made in the new software must be faulty where we need to fix it. Maybe the newly added component uses floats and the previous one uses integers. Nevertheless, this mismatch causes the test to fail. Therefore it should be fixed. Remedy: Fix the faults

2) Test Values are no longer valid — the values that we have been using, are no longer valid. Maybe because we came up with a new restriction in the system when adding the new modification. We then need to update the previous test values. The remedy is to delete or modify the test case

3) Expected output is no longer valid — Every test case has an expected output. — the previous regression test must have been expecting a number at the end as the result. But now, we are outputting a range name (grade) based on that number. So the previously expected output is no longer valid. Remedy: Therefore we need to change the test and update it.

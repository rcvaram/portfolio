How String works

String constant pool

In java, all objects are stored in Heap. Java has a specific area inside the heap for String and that is called String constant pool or String literal Pool.

If you are blocked by medium paywall, Read it here.

String can be created in two ways.

  1. String literal way
  2. String object creation
class Test {
  void test(){
     String fruit = "Apple"; //line 1
     String drink = new String("cola"); //line 2
  }
}

When the line1 is executed, java created a apple string literal in string pool and referenced in the stack for thread usage.

when the line2 is executed, java created an object however for the value it creates an string literal cola in string pool and it was used inside the cola object and referenced as drink in stack.

Duplicates are not allowed in the String pool.

If i create another fruit which values is Apple like below

String myFruit = "Apple";

No other string literal will be created It will point to the same literal as below.

This is the reason why Strings called as immutable.

If multiple variables reference the same String object,

  • changing one variable does not change the String object or the other variables.

The variable is made to reference a different String.

To understand deep,

Lets think We have three variables which points to the same String literal.

String fruit = "Apple";
String myFruit = "Apple";
String favouriteFruit = "Apple";

Incase, If String is mutable, If change favouriteFruit to Orange then it would automatically change the fruit and myFruit values to orange.

favouriteFruit = "Orange";
// also
// fruit and myFruit also changed to "Orange"

But that’s not how String literal works,

when we update the favouriteFruit to “Orange”, We can see that only that reference is updated to Orange and fruit and myFruit will be still apple

String fruit = "Apple";
String myFruit = "Apple";
String favouriteFruit = "Apple";

System.out.println(fruit); //Apple
System.out.println(favouriteFruit); //Apple

favouriteFruit = "Orange";


System.out.println(fruit); //Apple
System.out.println(favouriteFruit); //Orange

“Orange” is different string and not the same string “Apple”. “Apple” is not able to changed and that’s why Strings are immutable.

Why it was confused initially,

When we print the favouriteFruit, It printed as orange after reassignment, so looks like the the same string “apple” was changed. That is because we used the same variable.

But in Reality,

The String “Apple” was not changed. Still “Apple” exists in the string constant pool, What actually happened is a new String “Orange” has been created and the favouriteFruit variable is pointing to this new String Orange

Once the String is created in the String constant pool, its never get changed it will be deleted by Garbage collection.

So what would happen If we do String concatanation?

String myFruit = "Apple"; //Line1
String homeFruit = "Sivaram" + myFruit; //Line2
  1. Java creates the Stirng literal “Apple” in the String pool.
  2. myFruit reference will be in the Stack and pointing the String pool.
  3. For the second line, Java creates the String literal “Sivaram” in the String pool.
  4. using “Sivaram” and “Apple” literals, a new String object will be created as “SivaramApple”.
  5. homeFruit references this new String object.
  6. The original literals “sivaram” and “Apple” remains unchanged in the String literal pool.

In some case, when both operans are compile-time constants (“Sivaram”, “apple”) compiler may optimize it to a single pooled literal “SivaramApple”

This Post key takeaways are

  1. String literals are stoed in the String pool (a specific area of Heap)
  2. Strings are immutable since existing String objects are never modified
  3. Concatenation with a varaible creates a new String object at runtime.

Why Java is not 100 % OOP Language?

Interview Questions → Java


Why Java is not 100 % OOP Language?

  • Java has primitive types: boolean, byte, int, long, double, float, char and short.

How does java adapt to the OOP with these primitive types?

  • Java wraps these primitive classes into an object of that class.
  • int is wrapped as Integer

Why pointers are not supported by java?

  • Pointers will increase the complexity of the program which contradicts the simplicity code of Java.
  • Pointers directly access the memory there will be a security vulnerability Java provides an abstraction to enhance memory management.

What is JIT compiler in Java?

  • JDK converts the source code into byte code. JRE has an interpreter & JIT. The interpreter will convert the byte codes into machine code line by line, on the other hand, JIT will convert the bunch of bytes code into machine code.

Why String is immutable in Java?

  • String Pool requires the string to be immutable otherwise shared reference can be changed from anywhere. 

What is a marker interface? 

A marker interface is an interface defined as the interface without any data & methods. These are used to tell the compiler/ JDK to tell some specific information. 

  • Clonable
  • Serializable 

Can a static method be overridden? 

Override a mechanism where parent and child class have the method signature as same hence during the runtime based on object type the method will be selected. If we do the same thing with the static method then the parent method will be hidden and not used.

Which methods does Object class has?

  • Object clone()
  • void finalize()

  • class getClass()
  • String toString()
  • notify()
  • notifyAll()
  • wait() overloading methods

How can you make a class Immutable?

  • Declare the class as final hence the class can be extended by any other class.
  • Make all fields private hence no direct access to the fields
  • No Setters
  • All mutable fields should be declared with final hence They can not be reassigned. 
  • Initialize all fields via constructor performing a deep copy.
  • Getter methods should return the clones of the fields instead of real fields hence the fields can not be mutated.

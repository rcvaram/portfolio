Components in the JVM Memory Model

  • Heap → This is where our objects and their references will be saved/reside. Static variables, Static Objects and the references of the loaded objects are stored inside the heap memory. 
  • Stack → Local primitive variables, objects, and method parameters are resided. 
  • Method Area → The compiled classes are stored
  • Native memory → Other specific language codes will be resided
  • PC Register → Saves the information about the execution

Young Generation | Heap | Java memory model

It is a place for all new objects created will be resided. Once the young generation gets filled up, garbage collection will be kicked in. This type of garbage collection is called as minor garbage collection (minor GC).

Once this gc is completed, there are objects which are not considered garbage by gc they will be moved to the old generation. 

Older Generation | Heap | Java memory model

The Objects which went through a lot of life cycles of garbage collection and still, survived will be moved to the old generation. The Old Generation means the place where long-lived objects will reside. 

The garbage collection which happens inside the old generation is called major GC. This gc tries to find out the objects which can be considered as garbage and then it will remove the objects. 

Eden Space | Young Generation | Heap | Java Memory Model

Any new objects that are created will be stored in the Eden memory. Once the Eden memory becomes full, a minor GC will be triggered. During this process, the objects that survive the GC will be moved to either Survivor 1 or Survivor 2. During Minor GC, the Survivor spaces are also checked to ensure that they are empty before moving on to another Survivor space. Once objects reach a certain threshold age, they are moved to the older generation as I mentioned earlier, after the Minor GC.


Garbage Collection

Marking — GC identifies which objects are not used 
Normal Deletion — Marked objects will be removed from the heap
Deletion + Compacting — The memory allocations are grouped to ensure future memory allocation is faster. 

During the Garbage collection, it finds O3 & O4 not referenced in the code and it is not going to be used anymore in future. then GC will mark these O2 and O3 as non-used objects.

  1. It will remove the unused objects from the memory as below.

Garbage Collection Types

Serial GC — these are useful when we need to do marks & deletions simply in young and old generations. For simple apps, this can be efficient.
Parallel GC — same as serial GC however they can spawn n number of threads for the younger generation. It uses multiple threads to ensure the throughput. One thread for the old generation and multiple threads for the younger generation.
Concurrent Mark Sweep GC  — It does the garbage collection for only the older generation. This GC tries to minimize the garbage pause which happens during the GC. young generation uses the same algorithm as parallel GC.

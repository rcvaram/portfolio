Direct Notes: SSH Authentication with GitHub

I wrote this as a practical reference for my future self to remember what each command does and why I am running it.

1. Creation ssh key

ssh-keygen -t ed25519 -C "ram-key"

Skip if you do not need the explanation

/**
ssh-keygen command creates an ssh key pair that can be used for
any ssh connection.

This normally creates two keys
 1. private key - this should be secret
 2. public key - YOu can give it to someone who wants to connect with u

-t means the key type and I used Ed25519 cryptographic algorithm to 
generate the key.

-c means comment when we put a comment it doesnt go and do in the
encryption.

This is based on asymetric encryption so you have to know that how it works


I usually use default options to complete the key creation but
you can change

Enter file in which to save the key (/home/sivaram/.ssh/id_ed25519):
→ Enter

Enter passphrase (empty for no passphrase):
→ Enter

Enter same passphrase again:
→ Enter
It will give this at the end of the command...
~/.ssh/id_ed25519       ← private key, keep secret
~/.ssh/id_ed25519.pub   ← public key, add to GitHub
*/

2. Run SSH-Agent

eval "$(ssh-agent -s)"

Skip if you do not need the explanation

/**
This commands starts the ssh-agent and makes our terminal aware of it.

ssh-agent -s → This commands starts the agent and in terminal
it would give conceptually like below.

SSH_AUTH_SOCK=/tmp/ssh-abc123/agent.1234; export SSH_AUTH_SOCK;
SSH_AGENT_PID=1234; export SSH_AGENT_PID;

ssh-agent says I am running in backgroud and these are my properites.

eval → takes this properties and executes inside the 
current terminal shell.

Basically with eval command we ensure current terminal session aware 
of the ssh start.
*/

3. Load the private key for SSH Authentication

ssh-add ~/.ssh/id_ed25519

Skip If you do not need

/**
We know the ssh-agent is running so The agent needs access
to the private key so that it can use it
when SSH performs public-key authentication.  
The private key itself is not sent to GitHub.

This command adds our private key into the running SSH agent.

If you carefully see the ssh-agent is not the one who creates the key. 

we have created using ssh-keygen and then 
add the key to ssh-agent to manage it while we are using the SSH.
*/

4. Copy your SSH public key

cat ~/.ssh/id_ed25519.pub

Skip if you do not need

/**
This will show your public key in terminal
you can copy it so you can add it your place where you need to connect.
If it is github then you can add it in the github.
Please note that we copied the public key not the private key.
 private key should remains in your PC and 
should not be disclosure with others.
*/

5. Add the Public key to Github

  1. Go to this link — https://github.com/settings/ssh/new
  2. Add your title as you like to remember the laptop
  3. paste your public key in the key section

6. Test the Github Connection

ssh -T git@github.com

Skip if you do not need

/**
This command checks whether the computer can authenticate with Github
using SSH

1. SSH - starts an ssh connection
2. -T - tells SSH not to open an interactive terminal
3. git@github.com - connet to Github using the git SSH user.

git@github.com -- Github's SSH service expects the SSH username to be git.
GitHub associates the public key we uploaded with our GitHub account. 
During authentication, 
GitHub verifies that the client possesses the corresponding private key.
*/

7. Update the commit user

git config --global user.name "Sivaram Rasathurai"
git config --global user.email "cvaram96@gmail.com"
/**
The git stores this information locally.

When we make commit using
git commit -m 'test-commit'

Git creates a commit containing the metadata 

Author - Sivaram Rasathurai
Email - cvaram96@gmail.com
Message - test-commit
changes - ...

This is the reason you see sometimes the commit author name is different
compared to our username.

SSH identifies/authenticates you to GitHub.
Git config identifies the author recorded inside a commit. 

They are two different things.
